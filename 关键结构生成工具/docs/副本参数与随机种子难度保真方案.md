# 副本参数与随机种子难度保真方案（2026-09-21）

## 背景、问题和目标

工具把原模板部分 A/B 牌改成 C–N 关键结构后，模板、可用 A/B 种类和揭露顺序都变了。即使继续沿用原 DupPara1–10 和 Seed，也不能据此断言新模板与原模板消耗一致。目标是让新模板十档副本的裸胜、消耗、背包压力、时长和关键结构揭露节奏接近原模板，保持整体由难变易，同时让每项推荐可复核。用户提供原模板线上指标作为目标；本工具仅生成待审阅的新配置，不写线上配置。

适用于已导出且能关联原模板的关键结构替换。结构规则、难度或证据结论不影响用户生成和导出审阅方案，只影响默认推荐及风险提示；仅模板/配置损坏、身份不一致或无法安全写出时停止。仿真直接使用当前路径可读的模板与配置，不要求用户另行补齐版本、平台或 IAP 状态，也不自动声称消费命中。

## 已确认事实与证据边界

- `DupParaN = A种类数|RandomSeed|TowerLucky|B种类数`。随机种子进入初始 A/B 分配；幸运值当前不参与初始牌面物化，新方案默认逐档原样保留。依据：[局内行为与牌面复现交接手册](/Users/你的用户名/Desktop/玩家ReplayInfo局内行为分析与初始牌面复现交接手册.md)。
- `StrategyGroupId=1003` 与 `randomSeed_groupID` 是不同配置项。当前资料支持“1003 的副本1、2不施加结构降难度，后续副本按策略组配置逐步处理结构”；工具按当前可读代码和配置做方向性仿真，不要求指定客户端版本或平台，也不会把仿真冒充线上消费预测。[谜题结构降难度 Wiki](https://wiki.atcloudbox.com/pages/viewpage.action?pageId=277080406) 与当前只读 [`config_level_strategy_group.csv`](/Users/你的用户名/Projects/ulinkconfig/csv/config_level_strategy_group.csv) 可核对配置含义。
- [副本数据 CSV] 为841行、85模板、200–284关，1003有391行，Seed 观察值0–3。固定模板、同一副本、A/B数、策略组、生效策略、幸运值后，没有不同Seed的独立对照组；不能从此表识别Seed的单独因果效应，更不能建立可靠的“目标消耗→Seed”逆函数。进入人数约1002–7502，应按样本量和不确定区间评价；日期范围和指标单位仍需明确。十档总体趋势明显，但逐档观测值并不严格单调。
- [`difficulty.py`](../scripts/puzzle_core/difficulty.py) 的默认 A/B 牌面物化仍是稳定哈希代理；目标消耗校准在当前配置可用时会改用本地配置 Seed 仿真，失败时明确回退到该代理。两者都只用于结构风险的方向性排序，不是线上人均消耗预测；本地仿真标记为 `current_local_config_simulation`，代理结果标记为 `synthetic`。

## 本轮规则（可直接实现）

1. 默认替换侧按**原模板实际 Tile 数**判定：A ≥ B 时仅替换 A，A < B 时仅替换 B；相等归 A。用户明确选“仅A/仅B/A+B”时覆盖默认。若默认侧没有足够合格位置，给出该侧容量不足，不暗中切换另一侧。统计取导出时原模板快照，并记录在 manifest；不能从 DupPara 种类数或新模板残余牌量推断。
2. 每个原 DupParaN 独立处理。通常在被替换侧扣除这次实际替换出的不同 C–N 类型数；并非按替换 Tile 格数扣，也不从 DupPara1 重建其余九档。对 A 牌量更多或相等的模板，A/B 种类参考底线为4/3；B 牌量更多时为3/4。底线还会被替换后剩余 A/B 牌的三张组容量所限制，不会建议一个根本没有足够牌格支撑的种类底线。碰到有效底线允许**少扣**：`新值 = 原值 - min(计划扣数, max(0, 原值-该侧有效底线))`。原值已低于底线时不抬高它。若原模板牌量证据不可验证，不推断主侧或套用底线，只展示机械扣减及警告。
3. 原每档 Seed、Lucky 原样保留。上一步是**初始审阅基线**，不是消耗已对齐结论。例如原 `7|0|100|4`，替换4种 A 后机械值为 `3|0|100|4`，按 A 主侧底线先给 `4|0|100|4`；若目标消耗显示仍过易，可在校准中选 `5|0|100|4`，但不能凭空把5宣称为准确结果。
4. 主动选择“重做副本梯度”只改 A/B 走势，不能顺便把 DupPara2–10 的 Seed/Lucky 全复制为副本1。结果需区分“原梯度保真”与“人工重做梯度”，标注每档实际扣数。

## 下一阶段：给定目标消耗的参数与 Seed 校准

输入锁定原/新模板文件哈希、线上关卡位置、当前可读的十档配置、策略组、图案池与原模板每档目标指标。版本、平台与 IAP 状态不是运行前提；IAP 默认按未触发处理。若用户只提供人均消耗，工具仍可运行并给方向性方案，只是不把单一均值解释为裸难度或 Seed 的因果效果。

工具可直接用当前可用模板、配置和关卡位置运行：对每档枚举底线允许范围内的 A/B 种类数（包括少扣方案）和受控 Seed 候选，先按用户选择回放该档结构降难策略，再用当前本地配置、客户端同款旧版 A/B 分配算法仿真初始牌面，最后做原/新模板配对评估。缺少目标版本、平台或 IAP 状态不会阻断；默认假设 IAP 未触发，并把所有输入、指纹与假设写进证据。顺序策略、失效与补位按 Wiki 第85版实现；随机策略使用稳定的本地采样，不能冒充客户端某一局的唯一随机分支。历史数据用于方向性校准和备选排序；在未完成跨模板/跨版本验证前，不承诺达到某个人均消耗值，也不自动上线。

导出审阅表应至少包含每档原 DupPara、新 DupPara、计划/实际扣除 A/B 种类、Seed 变化、Lucky 保留、1003生效策略、原目标及样本量、模拟代理值/区间、风险与版本证据。配置表可生成供人工导入的候选行，但不写回 `config_level` 或 `config_level_list`。

## 自我审阅：科学性、可解问题与限制

- **可解决**：以模板牌量决定替换侧，防止把来源选错；对每档独立少扣且保留原梯度/Seed/Lucky，避免机械全扣导致主牌类型过少；独立客户端物化将来可以检验“相同Seed是否真的相同牌面”。
- **尚不能证明**：底线4/3是用户提供的经验先验，不是普适硬规则；有些特殊模板或1003后期结构替换可能需要更低值。保留原Seed不保证难度，改Seed也不保证达到目标消耗。现有CSV没有受控Seed对照，不能训练可靠的单Seed因果调整量。
- **验收门槛**：旧版与结构化分配分别做客户端回放向量核验；同输入跨运行一致；样本外按模板留出验证消费、裸胜、压力区间覆盖率；分层比较1003的十档，保留副本间局部噪声但约束总体变易。模拟与实测偏差过大时只输出人工审阅，不自动推荐一个“最优Seed”。
- **待补证据**：目标消耗的具体口径与容差、目标版本图案池/随机种子配置快照、不同Seed的可比测试样本、特殊模板的规则标签和1003实际执行版本。未经这些证据，工具不应声称已自动复刻线上难度。

核心风险是把合成策略模拟误当线上人均消耗，或把策略组1003误当随机种子组。可选优化是先用旧版物化模块做配对实测回放、再补结构化算法和实验校准；研发/数分需要共同确认版本、图案池、消耗定义和允许的误差范围。

## 已落地的目标消耗校准 Beta（2026-09-23）

工具新增只读接口 `POST /api/v1/parameters/calibrate-consumption`。输入为已解析新模板的 `selection_id`、线上配置集与关卡范围、Base64 CSV 历史副本数据、可选的 `target_overrides` 和 Seed 实验搜索开关。当一次选择中有多个新模板时，当前 `target_overrides` 的副本1–10覆盖值会对每个模板共用；如需不同目标，应分批调用，后续再扩展为按 source/output template 维度的覆盖。

当前 Beta 的实际计算链路：

1. 先从 `config_level` 读取原模板 DupPara1–10，应用“每档独立少扣、Seed/Lucky 保留”得到保真基线。
2. 默认将历史 CSV 中“同原模板 + 同副本 + 同策略组”的人均消耗按进入人数加权，作为该档目标；用户覆盖值优先。
3. 只在“保真基线→原参数”区间枚举 A/B，因此是少扣回去，不越过原配置。默认 Seed 原样保留；打开实验搜索时也只枚举 CSV 中已观测的合法非负整数 Seed。Lucky 始终保留原值。
4. 同副本、同策略组的历史近邻只输出“历史关联点估计 + P10–P90 范围”。它受模板选择、版本和 Seed 混杂，不是因果预测。
5. 对每个入围参数运行显式 source/candidate 单档配对模拟。若选中配置集同目录存在 `config_client_level_tile.csv` 和 `config_client_tile.csv`，使用线上位置中最小的一个位置执行当前本地配置 Seed 仿真；多位置会返回所用位置和警告。缺表、Seed 不是 C# int、候选池不足或真正的结构化 `randomSeed_groupID` 不可重放时，自动回退为显式标记的 synthetic，不阻断推荐。默认模式会对可行 A/B 与 Seed 0–31 全量初筛，再对每档最多 9 个短名单做整盘仿真；也可改选保留原 Seed 的快速基线。
6. 十档联合选择对偏离原 A/B 梯度的转移加惩罚，并输出回升警告。每档返回主建议和至多两个真实不同的备选；若可枚举空间不足，显式告警，不伪造备选。
7. 工具从 `config_level_strategy_group.csv` 只读取得所选策略组的 `InstanceId1–10`。用户开启“考虑所选策略”时，按配置顺序执行策略1–8、失效跳过与列表补位；关闭时保留原始结构。页面与导出同时展示配置原始串、本地回放生效/失败策略和 CSV 实际观测的 `strategy_effective_list`。随机分支是可复现本地采样；缺表、多表冲突或非法配置时降级并警告。

响应固定声明 `claim_level=directional_beta`、`seed_causal_identification=false`、`client_strategy_1003_replay=false`、`config_mutation=false`，并新增 `structure_strategy_replay` 说明是否启用本地策略语义回放及其随机边界。`client_strategy_1003_replay=false` 仍保留，因为工具没有声称复现客户端内部的唯一随机流。响应还返回历史 CSV SHA-256、模板/manifest 指纹、覆盖副本数、样本人数和忽略行数；它只生成可审阅表，不会写回 `config_level`、`config_level_list` 或线上配置。

## 已落地的旧版 Seed 初始牌面仿真核心（2026-09-23）

[`legacy_materialization.py`](../scripts/puzzle_core/legacy_materialization.py) 已按当前可读客户端 `LevelDupGenerator.cs` / `CustomRandom.cs` 实现旧版链路，并不要求额外的版本、平台或 IAP 状态才允许运行。调用方提供当前可用的关卡序号、`config_client_level_tile`、`config_client_tile`、模板 A/B 占位的序列化顺序和当档 DupPara 即可仿真。

链路如下：

1. 选择 `StartLevel <= 当前关卡序号` 中 `StartLevel` 最大的 TileList 配置行。
2. 用 `uint32(1411242022 + RandomSeed)` 初始化 MWC `CustomRandom`，依次从 `TileList1`、`TileList2`、基础普通 Tile 列表抽取 `max(A种类数, B种类数, 1)` 个候选图案。输出去重且保留客户端抽取顺序。
3. A/B 各自先按三张一组近似均分，再各自从同一 Seed 重新初始化 RNG 并洗牌三轮，按模板原始序列赋值。
4. `iap_protect_cut_a_count` 是显式可选输入，默认 `0`（未触发 IAP 保护）；它只减少 A 有效种类数，候选池仍按原始 A/B 参数抽取。
5. 返回值包含算法版本、客户端源码证据标识、输入假设、所选关卡段、候选池、配置指纹和最终 A/B 位置赋值，便于对同一输入复核。

这个模块是初始牌面仿真，不把 Seed 直接解释为某个 Tile ID，也不声称 Seed 可直接预测人均消耗。当前 `config_client_tile.csv` 便捷解析路径使用配置行顺序表示客户端基础 Tile 资源顺序，并把该顺序写入指纹和假设；若后续可从运行时资源直接导出真实顺序，可将其显式传入而无需改算法。真正的 `randomSeed_groupID > 0` 结构化随机仍明确拒绝，不会静默退化为旧版洗牌。这与关键结构降难度的 `StrategyGroupId=1003` 是两个不同概念；1003 不会触发这个拒绝分支。
