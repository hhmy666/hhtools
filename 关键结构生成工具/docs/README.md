# 关键结构生成工具

这是关键结构生成工具的正式工作目录。工具在本机读取源模板、生成并验证候选；源模板始终只读，正式输出只写入用户配置的输出目录。

日常用户只需双击工具根目录的“启动关键结构生成工具.command”。网页入口位于 frontend/index.html，由本地服务加载；使用说明从网页右上角在当前页面内打开，不从启动器打开本 README。

## 根目录

根目录放置启动器和首次使用 README：

    ├── 运行数据/

运行设置默认保存到工具内的“运行数据/settings.json”，输出默认保存到工具内的“输出关卡模板/”。两者都可在设置中调整。

## 四步工作流

1. 导入模板：可整列粘贴模板 ID，或拖入一个/多个 _m.bytes。
2. 配置方案：设置批次方案，也可单独调整、追加多个成品或跳过指定模板。
3. 生成候选：查看精确进度、比较候选、查看质量分和求解轨迹，并选择需要导出的候选。
4. 验证导出：重新生成、独立复验、无覆盖保存，再回读输出。

顶部流程条从导入首屏开始显示。已完成步骤使用玉绿填充和对勾，当前步骤保持清晰，未开始步骤弱化。

## 首次使用和功能选择

首次使用先在“设置”中确认本机目录：

- Tile 源模板目录：只有通过模板 ID 导入时需要，始终只读。
- 输出工作区：用于正式模板、manifest、验证报告和审计记录，不得设在源模板目录内。
- ulinkconfig 目录：只有使用“一键配置新参数”或“目标消耗校准”时需要。

按目标选择入口：

- 生成带关键结构的新模板：使用“创建任务”。
- 为新模板快速生成 DupPara1–10：使用“一键配置新参数”。
- 根据原关卡人均消耗联合搜索 A/B 与 Seed：使用“目标消耗校准 Beta”。
- 查看或恢复当前本地会话任务：使用“任务记录”。
- 查看已落盘的 JSON、Markdown 或 CSV 验证产物：使用“验证报告”。

右上角“使用说明”会自动定位到当前页面对应章节，并支持按功能名、按钮文案或字段名搜索。

## 生成参数要点

以下用“默认”“硬规则”“提示”区分初始值、不可越过的约束和辅助说明。默认值可调整；硬规则由界面校验并由后端复核；提示解释口径，不额外构成限制。

- 支持 1–2 个谜题；多谜题可采用 X 左右、Y 上下或 Z 高低层。
- 结构门槛支持 4–9 步，中途三消回包不改变 s 命名所代表的门槛步数。
- “门槛前回收次数”默认 0，要求推荐解在门槛三消前恰好回收所填次数；`sN + r 次回收`会在第 `N + 3r` 次点击触发门槛。
- 回收次数大于 0 时需设置“首次回收前铺垫块数”，默认 2，表示首次三消前至少先点击 2 个非成组 Tile，因此不会出现前三步直接 EEE 回收；回收次数为 0 时不显示该字段。
- 塔内模式为禁止（默认）、允许、仅塔内。仅塔内均匀分配结构块，不计算静态谜题步数，以 tower 命名。
- 替换来源默认按每个原模板的实际 A/B Tile 总数选择数量较多的一类；数量相同时选 A。也可显式改为 A+B、仅 A 或仅 B。
- 默认来源在检查层数、塔模式和其他硬限制前就由原模板总数确定；若选定来源的可用位置不足，当次生成失败并引导手动改来源，不静默混用或回退到另一类。显式保存了 `prefer_a_else_b` 的旧任务仍按原语义回放：有可用 A 就只替换 A，没有可用 A 才改用 B；它不等同于新默认规则。
- 结构块使用 C–N；生成仍是 A/B 原位替换，不改变坐标、层、塔和阵型。
- **工具默认**：“结构块最大层间距”默认启用并设为 5 层，可改为其他非负整数或不限制。启用后按 `最高结构层 − 最低结构层 ≤ 设置值`硬校验；例如第 1–6 层的间距为 5。
- **默认**：新建方案的位置范围不限、对称约束关闭、分布方式为“紧凑”；这些是初始偏好，不是硬规则。
- **类型输入**：界面只提供“类型范围”或“确定数量”，不提供随机范围入口。旧请求仍兼容其随机范围字段并保留旧语义；新界面不提交该字段。
- **组数互斥**：标准模式的“每种类型组数”默认 1 组；自定义模式使用按类型排列的组数向量，两种模式只能选其一。每组固定 3 格：总格数 = 类型数 × 每种组数 × 3。例如 4 种类型、每种 1 组，共 12 格；自定义向量 `[2, 1, 1]` 表示 3 种类型分别生成 2、1、1 组，共 12 格。自定义每项必须为正整数。
- 新结构块不能 100% 压住直接下一层 Tile，也不能处于被直接上一层 Tile 100% 压住的位置。规则只检查相邻层的单块全遮，不禁止多块联合遮挡，也不扩展到更深投影。
- “难度目标”位于高级设置，默认使用“难度保真”。“标准关键结构”允许少量高压路径但要求策略模拟可通过；“强卡点”允许更高压力，只在用户主动选择时启用。
- “整板体验目标”同样位于高级设置。默认自动判断“内生门槛型 / 整板揭露型 / 混合型”；也可手动指定。自动分类置信不足时不在候选卡或详情中显示无解释力的占位结论；Top 2 只保留在诊断证据中，也不会按其中第一名获得推荐优先级。默认以线上 200–300 关样本作软目标，可关闭。
- “全类型长程型”和“串行机关型”是两个特殊机制预设，默认不启用。全类型长程型只支持单谜题、非“仅塔内”方案，强制 C–N 12 类×3，可选自动、固定 3 波或固定 4 波版本化语法；它已证明波次支配与每波 7 格安全退出，但当前尚未证明整盘悬置 1/2 张的持续上限，因此标为“证据不足”、不自动推荐；用户可人工选择，在应用内确认提示后导出，缺失证据轴留在 manifest 和验证报告中。策略抽样仅显示压力观测，不冒充全路径证明。规则未通过或明确未达难度目标的候选同样不自动推荐，但用户查看结论并确认后可以导出；候选身份、源文件或重写完整性错误仍会停止导出。串行机关型只支持 Z 向 high→low 双谜题、非“仅塔内”方案，用于上一簇完成后才释放下一簇的特殊结构。界面会禁用与当前方案不兼容的预设并显示原因，前后端均在提交时复核。
- **默认**：候选池生成 6 个；这是可编辑的搜索目标，不是质量硬门槛。预算耗尽时已找到的部分候选仍可进入审核。

### 塔内禁止时的百分比

- 禁止塔内生成时，结构块数量占比以非塔 Tile 数量为分母，上限可设至 100%；实际可生成数量仍受可用位置、完整三消组及其他生成约束限制。
- 最高层百分比只以非塔区域实际最高层为基准。
- 界面应显示换算后的实际 Tile 数量和最高层，避免用户误解口径。

## 候选审核

- 每个成功的成品项首次进入时，仅在存在明确推荐排序时默认选择“推荐 1”；没有推荐时保持未选择，不按候选编号猜测。用户主动清空选择后，系统不会再次替用户选中。
- 用户可更换、追加或清除选择，也可让部分模板/成品项不导出。
- 已有选择在切换页面和成品项时保持不变。
- 同一成品项可同时加入多个候选；每个候选都会独立导出，按选择顺序使用基础名、v2、v3……且不覆盖旧文件。
- 点击“完成本项，查看下一项”后进入下一成品项；“上一成品项 / 下一成品项”放在候选卡片与分组翻页之后，方便看完当前模板再切换。
- 候选详情提供“上一个 / 下一个 / 返回列表”，前后顺序与来源候选列表一致；首项禁用“上一个”、末项禁用“下一个”，不循环。返回时恢复来源列表页、排序、分页位置和已作出的选择，包括从详情跨页返回。
- 最多 3 个候选横向比较，视角、缩放、层范围和显示模式同步。
- “查看与播放”展示精确棋盘、质量分详情和后端已验证的求解轨迹。
- 候选卡采用紧凑密度，桌面端优先在首屏同时看见候选摘要和选择操作；“查看与播放”页面优先保证棋盘、求解轨迹、背包状态与本步说明同时可见。
- 当前已选候选同时使用玉绿描边、明确的“已选”文案和绿勾，不只靠按钮状态或颜色区分。
- 候选数量完全按用户配置搜索。推荐顺序为：硬校验 → 原型匹配 → 机制压力底线 → 与原模板难度距离 → 线上风格距离 → 布局打平。在“难度保真 / 标准关键结构”中，高机制压力候选不进入优先推荐；只有用户显式选择“强卡点”时，高压才不被当作越线，但仍需硬校验和安全通路。暂停、终止或预算结束时若只找到部分候选，仍可直接使用这些结果进入后续流程。
- 部分完成时按模板和成品项列出“已找到 / 目标候选数”，因此可以直接判断是哪个模板缺候选；继续搜索只处理未完成的候选槽，已找到的候选保持不变。

### 难度模拟与推荐

- 候选卡只展示三个决策信号：体验原型、与原模板难度距离、机制压力。机制压力来自固定策略样本和揭露路径；未经真实玩家数据标定前，不称为玩家风险。
- 每个候选会分别代入原模板的 DupPara1–10，比较策略样本通过率、7 格背包样本失败路径比例、首次回收、首次满包，以及随机、贪心、局部最优、解锁优先和压力/对抗五类策略结果。五类策略分别报告，不按试验条数混合；这些值是固定策略样本的方向性证据，不等同于真实玩家胜率。
- 系统同时模拟原模板作为基线，计算候选与原模板的预测难度距离；距离越小，越符合“难度保真”。在完成带真实结果的等价带标定前，该距离只用于相对排序，不使用人为数值阈值宣称“已等价”或“不等价”。
- 整板体验报告包含版本化复合结构簇图：簇成员同时考虑直接遮挡、投影近邻和空间近邻；簇间依赖会穿过 A/B 桥接并输出 DAG，以及并行、投影重叠、严格串行三类关系。这些拓扑会进入体验指纹，避免只换少量坐标的候选被当作真正多样。
- 线上风格参考按“结构规模 + 原型”分层。样本充足时使用该分层；样本不足时向同规模样本收缩；原型不确定、分层缺失或规模缺失时显式回退。报告会展示子样本数、有效样本数、参考置信度、收缩权重和回退原因，不用 1–2 个模板伪装稳定规律。
- DupPara1–10 应总体逐步变易。后半段副本比前半段更难时，候选会被降级；明显违背所选难度目标时不进入优先推荐。
- 界面会显示模拟覆盖状态。找到完整原副本参数时标记为完整覆盖；缺失、重复冲突或只能使用结构参考时会明确标注，不把参考模拟包装成精确线上胜率。
- 策略模拟用于候选间方向性比较，仍不能替代真实玩家价值测试或线上难度数据。
- “查看本候选整板体验依据”会逐项展示硬校验、原型得分、难度距离、线上风格距离及分项、机制压力信号、已观测风险、证据覆盖和揭露曲线。旧记录缺失时显示“方向性参考 / 未评估”，不猜测数值、不报错。

### 棋盘与层数

- 精确棋盘采用与 Unity 关卡编辑器一致的俯视表达，不使用会改变位置判断的等距透视。
- 选择“显示至第 N 层”时，只显示第 1–N 层，即显示 `layer <= N` 的 Tile；高于 N 的 Tile 隐藏。
- 普通 Tile 不因层数改变屏幕坐标；塔由模板中的塔数据识别并按塔方向显示堆叠，不通过坐标猜测塔。
- 候选卡、候选详情、求解轨迹和横向比较使用同一套层数口径与视图规则。
- 详情棋盘中的 A/B Tile 使用 80% 透明度，以便隔层观察 C–N 结构变化；结构块保持实色。

旧的“综合质量分”在界面中已改名为“布局打平分”，并可展开查看这个候选自身的分项与计算结果。它只在硬校验、原型、机制压力、难度距离和线上风格相当时打破平局，不是玩家风险或 0–100 百分制。硬校验通过也不等于所有玩家路径或客户端运行时已经完全验证。

## 长任务控制

生成候选和正式复验导出都支持：

- 暂停；
- 继续；
- 终止；
- 继续搜索未完成项，并保留已经找到的候选。

任务采用安全检查点协作控制，因此暂停或终止不是强杀进程。界面会先显示“暂停中”或“正在终止”，在当前有界求解/写入步骤完成后进入已暂停或已终止状态。

进行中界面显示已完成/总数、进度、当前阶段、已用时、服务心跳、成功/失败/待处理数、实时运行记录与控制按钮。运行记录来自后端真实任务事件，不用前端根据一个状态字段伪造日志。进入候选页后，任务概览和完整事件时间线仍可展开查看；没有可靠样本时不会伪造精确 ETA。

正式导出进入事务提交阶段后短暂不可暂停或终止，以防产生半份输出；界面会明确显示“正在提交”及原因。

### 恢复边界

- 可以离开当前页面或切到其他功能，只要启动窗口和本地服务仍运行，任务可从“任务记录”返回。
- 关闭启动窗口、结束 Python 进程或重启电脑后，未完成的生成任务、暂停状态和未导出候选当前不能恢复。
- 已正式导出并回读通过的模板、manifest、验证报告和事务记录已经落盘，不随会话丢失。

### 失败处理与放弃当前任务

- “参数已证冲突”只用于必要条件或求解证据能证明组合不可能的情况，并引导调整当前模板参数。
- “当前预算未找到”不等于无解，主操作为“继续搜索未完成项”。搜索预算表示每个未完成候选槽的累计尝试上限；续跑只搜索旧上限到新上限之间尚未尝试的区间。提高上限通常会增加搜索时间，也会增加找到候选的机会，但不保证成功。界面会分别显示当前与推荐累计上限、本轮预计新增尝试、任务累计尝试和推荐档预计用时；历史候选槽命中率只作方向性参考，样本不足时明确显示“暂无法可靠估算”。
- **默认**：初始搜索预算为每个候选槽 2,000 次，预算是可调整的累计尝试上限，不保证命中。“当前预算未找到”不等于无解，可继续搜索未完成项。
- 在候选页调整单模板或应用推荐参数时，界面保持在当前流程；后台续跑会等待当前计算到安全点，继承已有候选和用户选择，只搜索指定模板 / 成品项尚缺的候选槽。
- “继续搜索未完成项”统一覆盖预算耗尽、中断、用户终止和暂时性异常等可恢复情况。已完成项与已有候选保持不变，只补尚缺的数量，避免“继续补齐”和“仅重试”两个相近操作造成歧义。
- 参数建议由失败原因驱动并进行小预算试算；卡片展示原值、新值、原因、影响和试算结果。“一键修改该参数并继续运行”只修改当前失败模板，再按新参数创建续跑任务；小预算未命中时会标明“尚未验证”，不会伪装成已经证明可生成。
- 创建任务后的配置、生成候选和验证导出步骤都提供“放弃当前任务，重新创建”。放弃会在安全检查点请求停止仍在运行的任务，并清空当前工作区，但保留任务记录、已落盘输出、验证报告和用户设置。
- 若正式导出已经进入不可中断的事务提交阶段，当前工作区可以离开，但该次提交会继续安全完成，避免生成半份输出。

## 一键配置新参数

该功能在左侧导航常驻，只读 ULink 配置，不回写 config_level.csv 或 config_level_list.csv。页内分为“线上关卡模板索引”和“未上线模板参数索引”。

两种索引共用同一组模板来源：

- 输入 aipuzzle 模板 ID，从当前输出目录查找，或上传 _m.bytes；
- 沿用本次会话中成功完成验证导出的模板。

从“验证与导出”成功页进入时，默认选中“沿用刚才导出的模板”，并可直接确认；没有本次成功导出时，才默认停留在“输入模板 ID”。输入有效模板 ID 或选择模板文件之前，“确认新模板”保持禁用，避免空提交。导入关卡模板页同样只有在当前方式已有模板 ID 或文件后才启用“解析模板”。

首次选择 ulinkconfig 根目录后保存到本机 Profile，后续自动复用。“线上关卡模板索引”关联 config_level_list 与 config_level，并按关卡区间展示原模板、线上位置、原 DupPara1–10 和新推荐 DupPara1–10。“未上线模板参数索引”会先从导出 manifest 解析新模板对应的原模板 ID，再自动检索 ulinkconfig 目录内所有可用 config_level。该模式不显示“配置集”选择，结果展示所有匹配的 LevelId、配置来源与 DupPara1–10；命中多行时显式标记重复原模板 ID。

### 参数计算

默认使用“保真副本参数”：

- DupPara1–10 各自独立计算，不从 DupPara1 重建其余副本；
- 每个 DupParaN 的 A Tile 种类数 = 该副本原 A 值 − 从 A Tile 实际替换出的不同结构块类型数；
- 每个 DupParaN 的 B Tile 种类数 = 该副本原 B 值 − 从 B Tile 实际替换出的不同结构块类型数；
- 原模板 A Tile 数量不少于 B 时，默认仅替换 A；否则默认仅替换 B，用户手动选择优先；
- 有原模板牌量证据时，A 主侧按 A/B=4/3、B 主侧按 3/4 作为经验底线，碰底线时可少扣；
- 每个副本原有的 Seed 与 Luck 保持不变，并保留原每档参数的来源；换模板后的实际难度梯度仍需单独验证，不等于已完成消耗复刻。

用户也可以主动选择“重做副本梯度”。该组方案以调整后的 DupPara1 为起点，按通用递减、保持一致、逐副本递减等规则重新生成 DupPara2–10；界面会明确标记这不是纯粹的模板结构保真测试。

## 目标消耗校准（Beta）

“目标消耗校准”是左侧导航中的独立功能，不依赖“一键配置新参数”的计算结果。它根据原关卡 Dup1–10 的实际人均消耗，联合搜索新模板的 A/B 参数和 Seed。

准备数据：

- 新模板：支持输入 ID、上传 `_m.bytes` 或沿用刚导出的模板。
- 历史副本 CSV：至少包含模板 ID、副本号、DupPara、关卡号、进入人数和人均消耗。`StrategyGroupId` 和 `strategy_effective_list` 均为可选列。
- `config_level.csv` 可选上传，只覆盖本次计算；不上传时读取当前 ulinkconfig。
- 页面布局：两个 CSV 上传控件同一行等宽；下方四个参数控件等宽排列。策略 ID 是三选一：`source`（和原关卡一致）、`1003`、`1004`。

计算规则：

- 消耗目标默认使用原模板各副本实际值。手动目标只覆盖已填写的 Dup，留空档仍使用原值。
- 结构降难策略 ID 仅提供 `source / 1003 / 1004` 三个选项。`source` 从 `config_level.StrategyGroupId` 逐模板读取；1003 与 1004 使用对应固定 ID。历史 CSV 不需要包含策略 ID。
- “结构策略仿真”可选考虑所选策略或忽略结构降难。考虑策略时依据已核对的 Wiki 页面 277080406 / PRD v85：每档分别读取自己的 `InstanceIdN`，空配置、0 或数量为 0 时不应用；模式 1 按配置顺序尝试并补位，模式 2 使用可复现的本地随机次序。是否从 Dup3 开始由当前策略组的实际十档配置决定，不是通用规则。工具先得到该档降难后的模板，再以该档 DupPara 与 Seed 物化 A/B 牌面。
- Seed 默认使用“A/B + Seed 0–31 联合搜索”：先用价值测试校正拟合筛选 A/B，再用轻量牌面距离筛选 Seed，只对短名单执行完整整盘仿真，最后联合选择十档参数。历史邻居仅作独立上下文。界面同时保留“保留原 Seed”快速基线，以及“在已观测 Seed 中搜索（含原 Seed）”；后者会在历史已观测 Seed 与原 Seed 中直接选择主推荐，不只是展示备选。
- Lucky 在每个副本保留原值。IAP 保护默认未触发；来源与假设会显示在审阅证据中，不作为禁止导出的条件。

结果与写入：

- 每个模板始终输出完整 DupPara1–10（含 Seed）；即使搜索空间内没有精确命中，也输出当前最接近值及偏差、置信和复核提示。整体排序优先级为 D1=4、D2=4、D3=2、D4=2、D5–10=1。
- 每档同时展示线上目标、拟合人均消耗估计、仿真难度距离、Seed/Lucky 变化、策略证据、证据等级和至多 2 个备选。
- 命中当前 200–300 关、s5、9–18 个结构块的校正范围时，“预期人均消耗”显示价值测试校正拟合；超出范围时显示保守基线。历史邻居只作独立上下文，不作为预期消耗来源。
- 校正拟合与目标偏差不超过 25% 时标记推荐；25%–50% 需要人工复核；超过 50% 标记不推荐。保守基线不会伪装成推荐；所有结论都不阻止导出或人工写入。
- “预期人均消耗”是有适用边界的拟合估计，不是 Seed 对消耗的因果证明，也不保证上线后精确达成。
- 每个模板可在机械扣减下限与原参数上限之间单独调整 DupPara1 最高参数并重算。不存在全局“最低 7”或“Dup1/Dup2 差值”硬规则。
- 可导出“校准审阅 CSV”和“DupPara 草案 CSV”。“一键写入配置”的备份和写入准备文件仅保存在工具自身的 `运行数据/配置备份/`，配置仓库内只原子更新用户确认的 `config_level.csv`，不新增 `.bak` 或临时文件。工具目录与配置目录跨磁盘、无法原子替换时直接拒绝写入，可导出草案后手动导入；不修改策略表，不提交 Git，也不发布线上配置。

## 安全边界

- Tile 仓库与 config_level_list 始终只读。config_level 默认只读；仅在“目标消耗校准”中由用户确认“一键写入”时，才会在工具自身的 `运行数据/配置备份/` 保存原文件后，原子更新指定 config_level.csv。不会向配置仓库添加备份或写入准备文件，也不会自动迁移或清理历史备份。
- 模板 ID 入口的仓库路径与输出路径由每台电脑首次配置，不能写死为某位同事的绝对路径。
- 候选阶段不写正式输出；正式导出使用排他锁、幂等键、防覆盖命名和磁盘回读。
- 本地服务只监听 127.0.0.1，并对状态变更请求校验同源会话和 CSRF token。
- 工具产品不检测、不调用也不依赖 Git；版本提交属于开发协作流程。
