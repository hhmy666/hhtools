# 关键结构生成工具 · UX 行为契约

> 本文档定义用户可观察的流程、状态、反馈、恢复和安全边界。
> 业务规则以后端求解器、验证器和用户最新确认为准；界面不得伪造精度或扩大验证范围。

## Canonical UI Map

| Capability | Canonical owner | Source of truth | Allowed variants | Verification |
|---|---|---|---|---|
| Select/Listbox | Native HTML select | DESIGN.md + UX-CONTRACT.md | native | keyboard + real-browser popup |
| Form | Semantic HTML controls + `app.js` validation adapter | UX-CONTRACT.md | create / edit | Node contract + Python API tests |

## 1. 核心对象和用词

| 名称 | 界面语义 |
|---|---|
| 源模板 | 从只读 Tile 仓库或用户上传文件读取的 _m.bytes |
| 成品项 | 一个“源模板 + 一组成品方案”；同一源模板可以有多个成品项 |
| 候选 | 一个成品项在同一配置下产生的一份可选结构布局 |
| 已加入导出 | 用户把一个或多个候选加入本次正式复验与导出；同一成品项允许多选 |
| 硬校验通过 | 固定 C–N 结构、替换坐标、塔归属、相邻层单块全遮和结构背包规则通过；不代表整关 A/B 图案已验证 |
| 机制压力 | 固定策略样本和揭露路径中的操作压力信号；未经真实玩家数据标定时，不等于玩家风险 |
| 已观测玩家风险 | 只有与玩家实验或线上数据标定后才可展示；没有标定时显示“未标定” |
| 综合质量分 | 相同成品方案内的兼容布局指标，不是硬规则、玩家风险或通用百分制 |

页面和接口可在内部使用 work item，面向用户统一显示“成品项”，避免使用 U1/U2 等未解释缩写。

## 2. 四步主流程

创建流程固定为：

1. **导入模板**：输入一列模板 ID，或拖入一个/多个 _m.bytes。
2. **配置方案**：先设批次默认，再为特定模板使用统一方案、只用本模板方案、统一方案加新成品，或跳过。
3. **生成候选**：查看任务进度，比较候选，查看质量分详情和求解轨迹，并为需要的成品项加入一个或多个候选。
4. **验证导出**：对所有已加入候选重新生成、独立复验，以无覆盖方式保存模板与报告。

### 流程条

- 从首屏开始常驻显示。
- 已完成节点使用玉绿填色和对勾；当前节点使用实心节点和步骤数；未开始节点为灰色。
- 已完成步骤可返回修改。若修改会使后续结果失效，进入前明确说明影响。
- 前置未完成时，后续节点不可点击，并显示禁用原因。

### 放弃当前任务

- 创建任务后的第 2–4 步常驻提供“放弃当前任务，重新创建”，但视觉等级低于该步骤的主操作。
- 操作前使用应用内确认弹窗说明影响，并默认聚焦安全操作。确认后在安全检查点请求停止仍在运行的生成或导出任务，清空当前工作区并返回导入页。
- 放弃只清理本次工作上下文；任务记录、已正式落盘的模板与报告、最近导出记录、仓库路径、输出路径及其他用户设置均保留。
- 若导出已进入 `committing`，不能中断事务提交。界面返回新任务前应明确说明该提交会继续安全完成，且其结果仍可从任务记录或输出目录查看。

## 3. 导入和配置

### 3.1 导入

- “输入模板 ID”和“上传模板文件”为两个入口，均不修改源文件。
- 模板 ID 从用户首次配置并已持久化的 tile 仓库路径查找；上传文件不要求配置该路径。
- 输出根目录首次使用时提示默认位于工具旁的“输出关卡模板”文件夹，之后自动复用，也可随时调整。
- 设置中的“模板仓库目录”只指定实际存放 `_m.bytes` 的目录，提供“选择模板目录 / 手动输入路径”两个互斥入口。默认选择目录；手动模式使用完整路径。共用同一个路径草稿，切换和取消选择不清空、不自动保存。保存时沿用后端目录可读性、源输出隔离等校验；失败显示字段旁错误并保留输入，重复提交被阻止。重新保存未改动的旧路径时保留原仓库信任边界。
- 多文件中单项解析失败，不得清空其他成功项。每项显示文件名或模板 ID 与可操作的失败原因。

### 3.2 批量与单模板方案

- 批次默认方案应用到所有未单独调整的模板。
- 单模板支持：使用统一方案、只用本模板方案、统一方案加本模板新增、本批次不生成。
- 同一源模板可配置多个独立成品项，如分别生成 s5 与 s6；它们不等同于一个双谜题 s5s6。
- 表格不设“来源”独立列。统一、本模板和新增关系只作为方案后的浅色说明。

### 3.3 关键参数

本节用“默认”“硬规则”“提示”区分初始值、不可越过的约束和辅助说明。默认值可由用户调整；硬规则由界面校验并由后端复核；提示用于解释取值，不额外限制生成。

- 谜题数量为 1–2 个；多谜题可选 X 左右、Y 上下、Z 高低层。
- 结构步数支持 4–9；中途三消回包不改变结构门槛步数的定义。
- 塔内生成有禁止（默认）、允许、仅塔内三态。“仅塔内”不计算谜题步数，以 tower 命名。
- 替换来源支持 A+B、仅 A、仅 B，以及默认的**原模板 A/B 数量较多者（相同选 A）**。
- 默认规则按单个原模板的实际 A/B Tile 总数判断，并在层数、塔模式和其他硬限制过滤之前锁定一种来源。若数量较多的来源在当前限制下位置不足，应显示失败或引导用户显式改为仅 A、仅 B 或 A+B，不静默混用或回退到数量较少的一类。
- 旧版请求中显式指定的 `prefer_a_else_b` 保留原语义：在当前限制下有可用 A 就只替换 A，可用 A 为零才使用 B；搜索与独立校验须一致。界面回显为“兼容旧任务”选项，不得静默改成新默认规则。
- **默认**：结构块位置不设位置范围限制，对称约束关闭，分布方式为“紧凑”。这些是新建方案的初始偏好，不是硬规则；用户可调整可选项。
- **类型输入**：界面只提供“类型范围”和“确定数量”两种入口，不显示随机范围入口。旧请求中的随机范围字段仍须兼容解析，原请求语义保持不变；新界面不生成该旧字段。
- **组数互斥**：标准模式使用“每种类型组数”，默认 0（随机分配）；填写 0 表示不固定各类型组数，候选按锁定 Seed 在全局结构块数量上下限内确定性随机分配，且每类至少 1 组。自定义模式使用按类型排列的正整数组数向量。两种模式互斥，只能提交一种。每组固定 3 格：标准模式填写正整数时，总格数为“类型数 × 每种组数 × 3”；例如 4 种类型、每种 1 组，共 `4 × 1 × 3 = 12` 格。自定义向量 `[2, 1, 1]` 表示 3 种类型分别生成 2、1、1 组，共 12 格。
- **结构块数量下限**：支持按占比、按数量、不限制；新建默认按占比 0%。占比分母与数量上限一致，数量按本次新增结构块计数，不包含源模板既有结构块。实际最少数量向上取到 3 的倍数，上限向下取整组；下限超过有效上限时拒绝生成。固定组数不足下限时明确报错，随机组数在上下限之间分配，独立导出校验同样检查下限。旧请求缺少下限时仍不设下限；旧请求省略组数或显式为 1 时保持历史 1 组；新建方案显式提交组数 0。
- **默认**：候选池为 6 个；初始搜索预算为每个成品项 2,000 次。两者均可由用户调整，候选数及预算的可调范围仍由服务端允许值约束。
- **共享上限与提前完成**：同一模板/方案的全部候选共用搜索上限，每个通过独立校验且不重复的候选立即保留并显示。达到目标数量立即停止，不为排名跑满剩余预算；推荐只在已找到的候选内排序。增加上限仅搜索新增次数，参数修改则为受影响项重新开始计数，已有候选及人工选择保留。取消发生在校验期间时最多重试当前未完成的一次，不跳过尚未保存的结果。
- **精准模式**：配置页可显式进入或退出。进入前保存当前批次统一方案及全部单模板方案；进入时覆盖候选数为 3、每个成品项初始预算为 20,000、最大层间距为 5、位置为不限制、对称为关闭、分布为紧凑，其余字段保持原值。退出时恢复进入前保存的方案；若页面直接载入精准配置且没有会话快照，则恢复普通模式默认值。
- **精准模式候选门槛**：返回候选必须同时满足配置硬规则、整板硬校验、所选难度目标、副本梯度安全，且机制压力明确为低或中。高、未评估或任一结论未达标都不返回；预算耗尽时可少于 3 个，不使用不达标候选补位。普通模式继续保留“方向性结论 + 人工审阅/确认导出”的既有流程。
- **工具默认 + 硬校验**：新建方案默认启用最大层间距 5；该设置可改为其他非负整数或不限制。启用后，层间距定义为 `max(layer) - min(layer)`，候选必须满足 `max(layer) - min(layer) ≤ 设置值`。例如最低第 1 层、最高第 6 层，间距为 5。
- 谜题单元可使用三的倍数数量并允许中途回包。
- “每个成品项搜索上限”属于高级设置，放在“复现与高级设置”内，不与谜题数量、候选数量等常用参数并列。
- 候选数量默认 6。它是可编辑的搜索目标，不是候选质量硬门槛；预算结束时已找到的部分候选仍可进入审核。
- “难度目标”属于高级设置：默认“难度保真”优先贴近原模板且 7 格背包优先无失败路径；“标准关键结构”允许少量失败路径但要求策略模拟；“强卡点”只在用户主动选择时允许高压路径。
- “整板体验目标”属于高级设置：默认“自动判断”；也可指定“内生门槛型 / 整板揭露型 / 混合型”。这三个原型分别侧重 C–N 自身解锁顺序、A/B 分批揭露与释放、两种机制共同作用。
- 特殊机制预设只有“全类型长程型”与“串行机关型”，默认不启用。前者只适用于单谜题、非“仅塔内”方案，强制 C–N 12 类×3，并使用版本化的 3 波或 4 波语法；“自动”会依次尝试两种语法。后者只适用于 Z 向 high→low 双谜题、非“仅塔内”方案，要求上一簇完成后才释放下一簇。
- 前端会根据当前方案禁用不兼容的特殊预设并显示原因；提交前再校验一次，后端仍会独立拒绝过期或绕过界面的不兼容配置。
- 全类型长程型当前能证明波次支配关系与每波至少一条 7 格容量安全退出路径，但不能仅靠结构内遮挡证明整盘 A/B 移除路径中“只露 1/2 张”的持续时长上限。该项证据必须显示为 `not_proved`，特殊预设和复合硬校验保持 `inconclusive`，不得自动推荐或显示为已证明；用户可人工选中，在应用内二次确认后导出，服务端独立复验并在 manifest/报告中记录未完成的证据轴。策略抽样只能作压力观测，不得包装为全路径证明。
- 通用证据状态遵循 `proved / inconclusive / disproved`。候选页的“样本优选”仅表示五项策略样本通过率合计最高，不代表难度或全部规则已通过；已明确规则失败的候选不参与优选。默认加入的候选仍保留原证据状态，需要人工确认的导出仍显示确认提示。服务端会再次计算结构规则、整盘完成、难度目标、副本梯度安全和难度证据等级，并把原结论与人工决定写入 manifest、JSON 和 Markdown 报告。候选身份不一致、模板无法安全重写等技术完整性错误不可绕过。
- “线上 200–300 关参考”是默认软目标，不会把样本常见区间变成新的硬校验；用户可在高级设置中关闭。
- “门槛前回收次数”默认 0，表示推荐解在指定门槛类型第一次三消前，恰好完成多少次其他结构三消；门槛三消本身不计入。`sN + r 次回收`的门槛点击步数为 `N + 3r`。
- 回收次数为 0 时，不展示额外铺垫字段；例如 s5 的推荐解第 5 次点击发生首次消除。回收次数大于 0 时，“首次回收前铺垫块数”为必填，默认 2；它表示第一次三消前至少点击的非成组 Tile 数，因此默认最早在第 5 次点击发生第一次回收，避免前三步直接 EEE 回收。
- 回收约束只承诺后端输出的安全完整推荐解恰好满足所填次数；不得把它描述成所有玩家路径都只能如此。必要条件冲突在搜索前直接说明，例如结构块数不足以满足 `S ≥ N + 3r`。
- “结构块最大层间距”限制同一成品候选中结构块最高层与最低层的差，即 `max(layer) - min(layer) ≤ 设置值`。新建方案默认设为 5；可改为其他非负整数，也可改为不限制。一旦启用，就是生成候选的硬限制，而不是推荐提示。

### 3.4 禁止塔内时的百分比口径

当“塔内生成 = 禁止”时：

- 结构块数量占比的分母只计算**非塔 Tile 数量**，塔内 Tile 不得进入分母。
- 占比输入上限为 100%，不额外限制为 50%；实际数量仍须满足完整三消组、可用位置及其他生成约束。
- 最高层百分比的基准是**非塔区域实际最高层**，不是整个模板（含塔）的最高层。
- 示例：整模板最高 12 层、非塔最高 8 层、最高层限制 50% 时，结构块最高不得高于非塔第 4 层。
- 界面在字段下方显示当前口径和换算结果，如“按 120 枚非塔 Tile 计算，最多 60 枚”“按非塔最高 8 层计算，最高第 4 层”。
- 没有可用非塔 Tile 时，应阻止提交并说明原因，不用 0 或整模板数据代替。

当塔模式为“允许”或“仅塔内”时，使用对应模式的实际候选池口径，并在字段旁明确显示，不沿用“非塔”文案。

## 4. 长任务状态模型

生成候选与正式复验导出都使用同一套协作式任务控制。任务只在安全检查点响应暂停或终止，因此请求后可能短暂显示“暂停中”或“正在终止”。

### 4.1 状态

| 状态 | 用户看到的含义 | 可用操作 |
|---|---|---|
| queued | 已进入队列，尚未开始 | 终止；后端允许时暂停 |
| running | 正常运行 | 暂停、终止 |
| pause_requested | 已请求暂停，等待当前有界步骤完成 | 继续、终止 |
| paused | 已在安全点暂停 | 继续、终止 |
| cancel_requested | 已请求终止，等待安全点 | 无重复终止；显示等待说明 |
| committing | 正在提交正式输出的不可中断窗口 | 暂停/终止不可用，并说明通常很短 |
| completed | 全部完成 | 查看结果 |
| partial | 部分完成、只找到部分目标候选，或其余项失败/被终止 | 使用已有候选继续；也可按失败原因继续搜索、调整参数或重试 |
| failed | 未得到可用结果 | 查看原因；按原因调整参数或重试 |
| cancelled | 已在安全点终止 | 查看已保留结果、继续搜索未完成项 |

“终止”属于高影响操作。首次点击打开应用内确认弹窗，明确任务名称、已完成内容会怎样处理和未完成内容会停止；默认焦点落在“继续运行”。

### 4.2 生成候选进度

进行中界面必须同时提供：

- 已完成成品项 / 总成品项、百分比和稳定进度条；
- 当前阶段的人类可读名称，例如“准备模板”“搜索结构”“独立硬校验”“整理候选”；
- 已用时间；
- 服务状态和最近一次进度更新时间，用于判断是否仍在运行；
- 成功、失败/取消、进行中/待补齐和已得到候选数；三个成品项状态桶必须互斥且合计等于成品项总数。
- 来自后端任务事件的实时运行记录；
- 暂停/继续与终止；
- “可以离开当前页面，但需保持启动窗口运行”的明确说明。
- 每个成品项按用户设置的候选数量搜索；已找到 `N / 目标数`要即时显示并保留。暂停或终止后只要已有候选，就允许使用这些候选进入选择、复验和导出，不因尚未补齐目标数而把整项标为失败。
- 继续搜索统一使用“继续搜索未完成项”：已有候选原样保留，只为每个成品项尚缺的候选增加尝试，不再并列出现“继续补齐”和“仅重试未完成项”。
- 续跑前展示每个未完成成品项的当前累计上限、推荐累计上限和下一轮预计新增尝试，同时展示任务累计尝试。新增次数不得乘以缺少的候选数量。预计用时只对应后端推荐档；用户改选档位后须明示当前档未单独估算。因为找到足够候选即停止，当前记录不能可靠预测续搜成功率，不显示伪造百分比；用户可在后端允许范围内选择下一档预算后继续。

不得凭空计算精确剩余时间。若缺少可靠 ETA，显示“预计剩余时间：计算中”或基于同一任务已完成项给出“粗略区间”，并标注“会随模板复杂度变化”。

暂停和终止到达安全点可能受单次求解尝试耗时影响，界面必须保持请求状态和心跳，不把等待误报为卡死。

任务事件按服务端顺序号和时间展示，至少包含排队、开始、当前成品项进度、暂停/继续/终止请求、提交与最终状态。前端不得用“最后进度时间 + 当前阶段”拼出一条看似真实的日志。所有候选补齐后直接展示候选列表，不显示生成进度和重复的批次清单；部分失败或已终止时保留失败摘要、对象、原因和下一步。生成页不单独展示“本批模板与候选”清单，失败、中止或暂停后的未完成项在候选计数旁提供“查看原模板”，复用逐层查看弹窗。

### 4.3 正式复验与导出进度

导出页面复用任务状态轨，并展示：

- 已处理候选 / 待导出候选总数；
- 当前候选和阶段：准备选择、复验请求、初始化工作区、工作区检查、提交输出；
- 已用时间、最近活动和完成/失败数；
- 暂停/继续与终止；
- 已落盘文件仅在磁盘回读成功后标记“已保存”。

进入 committing 后禁止暂停和终止，保留当前阶段与说明：“正在完成事务提交，为避免产生半份输出，此阶段不可中断。”

### 4.4 继续搜索与参数调整

- “继续搜索未完成项”覆盖候选未补齐、预算未找到、cancelled、pending 和服务中断等可恢复状态；已完成候选保持不变。
- 只有静态必要条件或求解证据能证明组合不可能时，才标为“参数已证冲突”，并显示具体冲突与“调整此模板参数”。
- 搜索预算耗尽但未找到候选不等于无解，应标为“当前预算未找到”，主操作为“继续搜索未完成项”；不得宣称相同参数必然失败。
- 参数建议由主要淘汰原因驱动，后台先进行有界小预算反事实试算。只有实际得到并硬校验通过候选，才标“已验证可生成”；否则只能写“预计提高成功率”。
- 建议卡片必须显示原值 → 新值、原因、可能影响和试算结果。“一键修改该参数并继续运行”只修改当前失败模板并在当前流程内续跑，展示前后差异且不改动其他结果；已验证建议和“未验证但可尝试”的机会建议必须如实区分，其他未验证建议不可一键应用。
- “调整此模板参数”在候选页内打开可访问的模态框，复用现有方案字段，只编辑当前模板和当前成品方案；取消不产生修改，保存后返回候选页并显示“已单独修改参数，可继续运行搜索”。任务终止、部分完成或失败时，任务页另提供“修改参数并继续”：修改方式独占一行，统一模式在其下方勾选模板，勾选区随模板数量自动换行增高；逐项模式只显示“当前编辑”下拉框，选项注明已有候选数量，只提交当前模板。选择区与参数表单一起在弹窗内容区滚动。不得跳回导入页，也不得清空当前候选、生成进度或人工选择。
- 已暂存的单模板修改可以“单独运行此模板”；底部“继续搜索未完成项”会把全部已暂存修改与其余未完成项一次提交。两种方式都在当前候选流程内继续搜索；服务端可以保留内部父子运行记录，但界面不得要求用户另建任务或离开候选页，并须持续展示继承的候选与进度。
- 未修改参数的普通续跑必须校验配置与种子一致。通过“修改参数并继续”发起的派生续跑允许保留旧候选，但必须按原始模板/方案身份隔离作用域；每个候选都保存生成时的方案与精确参数快照。若同一成品项包含实际配置不同的候选，或模板配置与统一方案实际不同，候选卡必须显示“非统一参数”和信息入口。相同配置续跑、仅改变配置来源、范围配置随机得到不同种类数或组数，均不触发标记。导出必须使用候选自己的快照，不能用新参数覆盖旧候选。
- 参数信息弹窗将实际不同的配置项置顶，用既有强调色和“不同”文字共同标识，并在当前值下注明统一方案或其他候选批次的对照值。比较依据是生成时保存的配置范围和组数规则，不将随机结果视为改动；统一方案无法唯一定位时，不猜测对照值。
- 参数快照解释、差异标记说明、配置页应用范围、回收规则、标准组数示例和层间距解释集中在使用说明，不占据表单或参数详情的主要内容。配置页的常规限制提示只显示“在当前参数设置下，结构块最高至第 N 层”，实际不可用或冲突仍显示错误信息。
- 导出任务重试失败或已终止项；已经正式提交并回读通过的输出不得覆盖。
- 操作名称始终为“继续搜索未完成项”，副文案明确已有候选会保留，避免误解为整批重跑。

## 5. 会话内恢复边界

- 生成任务、实时进度、候选与选择状态依赖当前本地服务会话。用户可以切换页面或暂时离开浏览器，只要启动工具的终端窗口和本地服务仍运行，就可从“任务记录”返回。
- 关闭启动窗口、退出 Python 进程或重启电脑后，**未完成的生成任务与暂停状态当前不能恢复**。界面和使用说明必须直说，不能显示“下次继续”。
- 已正式导出并完成磁盘回读的模板、manifest、验证报告和事务记录是持久文件，不随会话丢失。
- 已完成但尚未正式导出的候选不得承诺跨服务重启恢复。
- “任务记录”必须区分“当前会话任务”和“已落盘导出记录”，避免把内存状态误认为持久历史。

## 6. 候选选择与导航

### 6.1 默认与保持

- 进入“查看与播放”或横向比较后，当前页面仅显示候选审阅内容；生成进度与部分完成信息隐藏，轮询更新不改变这一布局。返回候选列表时恢复任务状态对应的信息，并保留原成品项、分页、焦点和选择。

- 每个成品项的候选已生成后，第一次进入候选页按五项策略样本通过率之和默认加入一项“样本优选”；10%+10%+10% 与 30% 平局，并列取原顺序第一项。五项全为 0、数据缺失或不合法时不推荐、不勾选。已有人工选择和主动清空均保持不变；仍在搜索的项不提前锁定首个候选。
- 候选摘要固定展示“随机策略 / 贪心策略 / 局部最优 / 解锁优先 / 压力测试”五项样本通过率，横向五等分、每列仅策略名和通过率两行，不单独占用标题行；分组名称“策略样本通过率”供辅助技术读取。缺失显示“—”，不当作 0；切换候选时指标位置与高度保持稳定，下面的模板指标优先留在首屏。
- 新导出只要求本事务的文件齐全并完成严格回读校验；已完成历史事务中的文件允许被用户归档或移动，不恢复、不要求放回原位。历史名称和版本仍保留，避免重复命名；现存文件内容冲突、路径逃逸及未完成事务仍拦截。对某个已完成事务本身重试时，依旧要求该事务文件齐全，不能把历史成功当作当前文件存在。
- 默认选择是可见且可撤销的，不等于已经导出。
- 用户后续更换候选、清除选择、切换成品项、打开详情或返回配置时，已有选择保持不变，除非配置被修改并明确使结果失效。
- 用户可将任意成品项设为“本项不导出”；不要求每个模板或成品项都选候选。
- 当前已加入候选在卡片右上角显示绿勾和“已选”，卡片使用玉绿描边；主操作变为“已加入，点击移除”。
- 同一成品项允许同时加入多个候选。正式导出时每个候选独立生成一个模板，并按加入顺序使用基础名、`v2`、`v3`……；绝不覆盖已有文件。
- 候选数量由用户配置决定。系统只在这批已找到候选中选出 1–2 个“推荐候选”，推荐标识不代替用户选择。推荐顺序固定为：硬校验 → 原型匹配 → 机制压力底线 → 与原模板难度距离 → 线上风格距离 → 布局打平。高机制压力候选仍可查看和人工选择，但不进入优先推荐。

### 6.2 完成本项并进入下一项

- 由于同一成品项允许多选，点击某个候选后继续停留当前项，方便继续加入或移除候选。
- 用户点击“完成本项，查看下一项”后才进入下一成品项，避免首次选择后自动跳走导致无法多选。
- 到达最后一项时停留当前项；用户可从顶部“进入验证导出”审核整批选择。
- 切换成品项不得改动其他成品项已经加入的候选。
- 失败或没有候选的成品项不作为可选择目标，但在导航中保留状态。候选页中每个 `0 / 目标数` 项都提供页内“调整此模板参数”，并明示调整不会清空其他已找到候选；保存后该行高亮显示已暂存状态，并提供“单独运行此模板”。中断、预算不足或暂时性失败项同时可使用统一的“继续搜索未完成项”，批量携带全部已暂存修改。

### 6.3 前后项切换

- 生成页与候选页共用“本批模板与候选”总览，列出全部模板、候选数量和状态；有候选的项提供直接查看入口。查看只切换视图，不停止后台搜索、不触发续跑、不清空人工选择。
- 每轮显示已保留、本轮新增和总候选数；旧服务未提供轮次数据时明确说明未记录，不用当前总数冒充新增。旧服务运行时只返回部分结果的，缺席模板显示“结果待同步”，不推断失败或丢失，不清理缺席模板的人工选择。
- 任务记录的同一任务控制请求互斥，发送续跑前重新核对状态；已在运行的任务不重复续跑。“查看任务与候选”始终是只读入口。
- 任务进度区与候选内容独立且从首次显示即等宽：运行中查看候选仍在上方显示实时进度，可收起候选返回日志；全部完成后直接展示候选并隐藏进度区。日志每千次搜索或找到候选时报告，保留任务状态变化，不展示内部剪枝说明。
- 配置页原模板和任务页原模板共用只读分层查看：全部层、仅当前层、第 1 层至当前层，支持前后层与层滑杆；显示 Tile 总数、非塔 Tile 数和非塔层数。任务页使用弹窗，支持关闭按钮和 Escape。所有模板均可查看原模板，不依赖候选或任务成功状态；后端只读取该任务锁定的源快照，不回读可能已经改变的仓库模板。

- 候选卡片、候选分组翻页之后的页面底部提供“上一成品项 / 下一成品项”，同时显示当前位置，例如“当前成品项 8 / 27”。顶部只保留重新生成、对比和进入验证导出。
- 同一模板存在多个方案时按成品项顺序导航，并同时显示模板 ID 与 s 签名，防止把它误认为模板去重后的计数。
- 键盘焦点在完成本项或手动切换后移动到新成品项标题，不跳到页面顶部。

### 6.3.1 候选详情导航

- 候选详情提供“上一个”“下一个”和“返回列表”。前后切换顺序必须与进入详情前候选列表的当前排序一致，不另行按 ID 或推荐分数重排。
- 当前列表中的首个候选禁用“上一个”，末个候选禁用“下一个”；禁用状态使用真实 disabled 语义并可见，不环绕到另一端。
- “返回列表”恢复打开详情前的列表页及其候选顺序、分页位置和可见上下文；从其他页面跨页返回时同样回到来源列表，不丢失已作出的选择。
- 前后切换到另一候选后，详情内容、候选标识和键盘焦点同步更新；候选选择状态保持不变。
- 详情页可直接将当前候选加入或移出本次导出；该操作与候选卡共用同一选择状态，页头同时显示当前模板和全部模板的已加入数量，避免将整批数量误认为当前模板数量。

### 6.4 横向比较

- 最多同时比较 3 个候选。
- 比较视图同步相机视角、缩放、层范围和显示模式。
- 差异摘要只展示可决策字段：步数/签名、结构种类与数量、A/B 替换、结构块最高层、线上风格距离、机制压力、布局质量分和硬校验范围。体验原型与难度距离只在至少一个候选拥有可靠值时生成对比行；其他候选在该行以破折号表示无可比值，不把占位文字当成数值比较。
- “加入对比”不等于“加入本次导出”；两个动作在文案、位置和状态上清楚区分。

## 7. 候选详情、质量分和求解轨迹

### 7.0 精确棋盘与层数

- 候选卡、候选详情、求解轨迹和横向比较均使用 Unity 关卡编辑器语义的俯视棋盘，不使用等距透视表现。
- “显示至第 N 层”展示所有 `layer <= N` 的 Tile，同时隐藏 `layer > N` 的 Tile。例如选择第 6 层时，可看见第 1–6 层，看不见第 7 层及以上。
- 普通 Tile 不随层数产生屏幕坐标偏移；同坐标或重叠 Tile 以层、平面坐标和稳定索引确定绘制顺序。
- 塔由模板中的塔数据识别并按方向展示，不能仅凭坐标判断。
- 切换层数时保持缩放和视图中心，以便连续检查上下层覆盖关系。

### 7.1 候选决策摘要

候选卡最多常驻三个体验决策信号，不再堆叠几何指标和技术免责文案。只有可靠依据的信号才展示；没有任何可用信号时，只提示用户查看棋盘和详细依据：

- **体验原型**：仅在分类置信度达标时显示内生门槛型、整板揭露型或混合型。置信度不足时 `primary` 保持空值，卡片、详情和比较表都不渲染该指标；Top 2 只保留在验证记录供诊断，不得回退使用 `automatic_primary` 冒充确定分类。
- **与原模板难度距离**：仅在拥有可比较数值、且配置覆盖与物化依据满足当前可靠性要求时显示。合成初始牌面、配置缺失/回退/歧义或无数值时，卡片不渲染该指标；详情说明未参与推荐的缺口。
- **机制压力**：拥有动态路径时可显示低 / 中 / 高；高机制压力同时显示“不优先推荐”。缺少动态路径时不在卡片中渲染该指标。

硬校验和推荐标识是独立状态，不计入“三个决策信号”的数量；棋盘、签名、结构类型和数量属于对象识别信息，不作为额外排序信号。

### 7.2 整板体验依据

“查看本候选整板体验依据”展开区须展示后端返回且达到可靠性要求的真实分项，不能只写“已统一纳入”，也不能把无值占位当成分析结果：

1. `hard_validation`：通过状态和原因；
2. `archetype`：仅当分类置信度达标时，展示设置原型、自动判定、三原型得分、分类置信度和基线；
3. `difficulty_distance`：仅当数值、配置覆盖与物化依据可靠时，展示总距离及已返回的分项；
4. `online_style_distance`：总距离、风格版本、冻结参考样本集、请求/实际参考分层、子样本数、有效样本数、参考置信度、收缩权重、回退原因、标定状态和分项；
5. `simulation_pressure`：机制压力等级、状态和具体信号；
6. `observed_risk`：只有已标定时才显示观测风险，否则必须说明“机制压力不等于玩家风险”；
7. `evidence_coverage`：静态几何、塔内排除、动态揭露、难度路径、玩家风险标定及其他已返回覆盖维度；
8. `reveal_curve`：各阶段已暴露 C–N、已凑齐类型、单张/两张悬置类型、释放 A/B 以及最早/中位/最晚路径。

旧记录可以缺失上述字段；界面必须优雅降级，不渲染无值的原型或难度距离分区，不报错、不猜测数值。难度策略样本依然单独展开：每个候选代入 DupPara1–10，检查随机、贪心、局部最优、解锁优先、压力/对抗五类固定策略探针，展示样本通过率、7 格失败路径、首次回收和首次满包。五类策略分别报告，不是真实玩家概率。

布局质量分作为独立的三级证据展开，保留真实公式、各分项贡献与原始维度；缺失分项的旧记录显示“未返回布局分项”。负分不使用红色失败语义，综合质量分不解释为玩家风险。

### 7.3 求解轨迹播放器

- 播放器重放后端已验证的点击顺序、背包插入、三消和结算后背包。
- 多谜题时使用“谜题 1 / 谜题 2”和对应 s 签名，不用 U1/U2。
- 每一步同步高亮棋盘 Tile、显示点击层数、点击前后背包和三消结果。
- 详情棋盘中的 A/B Tile 使用 80% 透明度，只保留必要轮廓与标签，使被其遮挡的 C–N 变化仍可辨认；C–N 始终保持实色。
- 支持上一步、播放/暂停、下一步、时间轴和 0.5× / 1× / 2×。
- 文案始终提示证明范围：轨迹假设外部 A/B 已清除，证明固定 C–N 结构顺序，不等同整关 A/B 图案仿真。
- 仅塔内模式不伪造静态求解轨迹，显示“塔内位置实时变化，本模式不计算谜题步数”。
- 详情页采用紧凑布局：棋盘高度以能看清结构为准，播放器紧贴棋盘下方；背包、点击 Tile、层数、插入后状态和三消结算属于首要信息，不得被超大棋盘推到长页面末尾。

## 8. 参数推荐规则

“一键配置新模板参数”只读 ULink 配置，不回写 config_level 或 config_level_list。功能拆分为两个同级索引：

- **线上关卡模板索引**：保留现有流程，联查 `config_level` 与 `config_level_list`，限定线上关卡区间，再根据 A/B 被替换的结构种类生成 DupPara1–10 推荐。
- **未上线模板参数索引**：与线上索引共用“输入模板 ID”、“上传模板文件”和“沿用刚才导出的模板”三个来源入口。系统先通过导出 manifest 解析新模板对应的原模板 ID，再按原 ID 匹配 `config_level.TemplateId`。该模式自动检索 ulinkconfig 目录中所有可用 `config_level`，不暴露内部“配置集”选择，也不依赖 `config_level_list`。结果展示现有 LevelId、配置来源和 DupPara1–10；同一原模板 ID 命中多行时不自动合并或猜测唯一值，须展示全部行并标记“重复模板 ID”。

- 从导出完成卡点击“一键配置新模板参数”时，默认选中“沿用刚才导出的模板”，且“确认新模板”为可用主操作。
- 刚完成导出且尚未完成本次参数计算时，“一键配置新模板参数”为主操作，“打开输出目录”和“创建新任务”为同尺寸次操作；完成本次参数计算后，“创建新任务”成为主操作，“打开输出目录”保持次操作。打开目录只使用该次已完成导出记录锁定的输出路径，不接受前端传入任意路径。
- 没有当前会话的最近导出时默认“输入模板 ID”。输入有效 ID、选择有效 `_m.bytes` 文件或存在最近导出之前，“确认新模板”保持禁用且不使用主强调。
- 导入关卡模板页遵守同一门控：只有输入有效模板 ID 或选择有效文件后，“解析模板”才启用并使用主强调。

### 8.1 保真副本参数（默认）

- DupPara1–10 每个副本都从该副本原参数独立计算，不从 DupPara1 重建后续副本。
- 每个副本的新 A Tile 种类数 = 该副本原 A Tile 种类数 − 从 A Tile 替换出的不同结构块类型数。
- 每个副本的新 B Tile 种类数 = 该副本原 B Tile 种类数 − 从 B Tile 替换出的不同结构块类型数。
- 扣除的是不同 C–N 类型数，不是 Tile 枚数。
- 每个副本的 Seed、Luck 和其他字段保持该副本原值。

### 8.2 重做副本梯度（显式选择）

- 通用递减、保持一致、每个/每 2 个/每 3 个副本递减统一归入“重做副本梯度”，只有用户主动选择时才从 DupPara1 生成 DupPara2–10。
- 后续策略递减时，A Tile 为 4 或更低时不再减少；B Tile 为 3 或更低时不再减少。
- 如果新的 DupPara1 原本已经低于阈值，则保留原实际值，**绝不为了满足阈值而抬高**。
- 示例：A=4 继续为 4，A=3 继续为 3；B=3 继续为 3，B=2 继续为 2。
- 该保护适用于通用递减、每 3 个副本递减、每个副本递减和每 2 个副本递减；“保持一致”本身不递减。

### 8.3 结果表达

计算结果表展示：修改前模板 ID、修改后模板 ID、原模板线上位置、原 DupPara1–10、新推荐 DupPara1–10，以及结构类型来源和策略证据。参数数量多时使用可水平滚动的语义表格，并冻结识别列，不通过缩小字体挤入一屏。

“新模板参数推荐”显示在模板来源/参数设置双栏下方并占满页面内容宽度。结果加载与横向表格不得改变上方双栏宽度，也不得压缩或隐藏“重做副本梯度”的选项。

### 8.4 目标消耗校准

- “按结构块种类数自动扣减首副本上限”为可选项，默认不勾选，API 缺省同样关闭。勾选后按加工源原参数减去实际替换的不同结构块类型数计算，A/B 分别扣减，不按格数或组数扣减，无需手填种类数。例：A=12、从 A 替换 5 种结构块，首副本 A 上限为 7；候选允许为 7 或更低并联合搜索 Seed。原机械扣减参数继续作为审阅参考，受影响类型的搜索下界采用既有 A=4/B=3 经验底线，低于底线的源参数不抬高。该上限在候选枚举和预估之前生效，所有备选也遵守；既有单模板重算不得超过自动上限，“最高参数”表示上限而非强制相等。关闭时沿用原有逐档搜索边界；切换后旧草案失效，防止两种模式的结果混用。
- 线上各副本人均消耗目标按副本顺序取不回升的本次目标，后一个线上值高于前一个有效目标时沿用前值；连续回升沿用压平后的目标。原线上值、样本与调整原因保留并展示，CSV 同时导出原线上值和本次目标。缺失副本不填造数据，不跨缺失项推断；手动目标保持用户填写值，不参与线上目标压平。
- 匹配失败、匹配歧义与服务错误使用前后缀下方的整行醒目提示区：明确数量、全部待处理模板、原因及处理操作，并保持“生成审阅草案”不可用；成功、加载和未上传采用对应状态。名称和长错误可换行，列表过长在提示区内部滚动，状态变化不覆盖用户输入。
- 下述加工源搜索上下界为未勾选自动扣减时的默认规则；勾选时以上述自动扣减边界为准，预测锚点仍保留加工源原参数。

- 界面名称为“目标消耗校准”，不显示 Beta 标签。文案面向关卡策划，主界面不用“合成回退 / 校正模型不适用 / 历史邻居”等内部术语；技术细节保留在默认折叠的运行记录。
- 上传 CSV 或修改前后缀后，先调用轻量匹配接口并展示每个模板对应的 CSV ID；歧义、未匹配或仍在匹配时不能启动长时间计算。手动前缀严格生效，不被 manifest 源 ID 或样本数量覆盖；CSV 匹配 ID 不替换实际加工源文件、哈希和阵型。
- 同一批的估算说明只在顶部显示一次，区分“本次上传 CSV 的关卡范围”和“模型训练关段”，不能把训练范围写成用户上传范围或新关段不可用。符合现有结构输入条件时，以原目标乘原模型的有界变化倍率，超训练关段返回 `transfer_estimate` 并正常展示预估值与目标差异；训练关段不匹配不再单独阻断计算。缺少目标、无效输入或不支持的结构才显示“暂无法预估”。有有效模拟距离时可标记“仅模拟排序”，模拟距离也缺失时标记“待人工确认”；不把原目标保留值和零偏差当成成功拟合。三项结果操作保持同排等宽等高。
- 加工源和线上源在 config_level 中都存在时比较十档参数；若不同，各档 A/B 分别以加工源配置为搜索上限，使用加工源的替换后参考参数作为搜索下限，十档梯度也参考加工源。按用户确认的工作假设，将加工源原参数消耗暂视为本次目标；加工源原参数同时用于倍率模型的原始输入和无关键结构原盘模拟。匹配的线上源保留目标消耗与原参数对照，不能伪称加工源已有实测。结果保留 `consumption_anchor`、`observed=false`、目标来源、各档边界及首副本 A/B 上限；重算不能越过边界。
- 搜索从加工源每档原 A/B 与原 Seed 开始向下枚举，沿用原搜索边界和结构条件。十档联合排序先最小化缺失消耗预估数，再比较已有副本权重下的目标消耗偏差，然后才比较模拟、梯度和次级差异；梯度不能压过更接近目标的有效预估。无有效预估时才只比较模拟证据，不把缺少模拟当作零距离。相同消耗与模拟成本下优先保留原 Seed，再作数值排序，禁止因字符串中“10”排在“1”前换 Seed。Seed 不虚构独立消耗系数，预筛和十档联合排序不宣称穷举后的全局消耗最优。

- 校准作为左侧导航中的独立功能，不依赖参数索引结果。模板来源支持输入 ID、上传模板文件和沿用刚导出的模板。
- 确认模板成功后滚动至“生成审阅草案”附近；整批生成与单模板重算均使用后台任务，显示真实模板/副本处理数、当前对象和耗时，完成后定位审阅结果。更改输入、前后缀、配置集或 Profile 路径后旧请求不得覆盖新上下文；运行中不得重复提交。
- 历史模板匹配优先使用完整原 ID，再解析生成前后缀和导出版本；仅接受唯一完整后缀匹配。可在当前批次填写前缀、后缀；内部原模板版本号保留，歧义明确报错。CSV/线上位置的匹配 ID 与 manifest 加工源 ID、SHA 分别保留，不伪造原线上阵型来源。
- 新草案携带服务器登记的配置来源，整批和重算结果仅可在相同 Profile、目录和配置集范围合并/写入。写入接口再次核验来源，拒绝跨环境使用草案；此前手工请求格式保留兼容。
- 校准表单的两个 CSV 上传控件在同一行等宽排列；其下四个参数控件等宽排列。策略 ID 控件为三选一：`source`（和原关卡一致）、`1003`、`1004`；选择 `source` 时逐模板读取 `config_level.StrategyGroupId`，其余两项使用对应固定 ID。布局不得把选项挤成非等宽或令字段文案换行遮挡。
- 输入包括历史副本 CSV、消耗目标来源、结构降难策略来源、是否考虑结构降难与 Seed 方案。系统从历史表内关卡号自动识别范围，不要求关卡段起止，也不展示内部配置集。CSV 只强制要求模板 ID、DupPara、副本编号、进入人数与人均消耗；`StrategyGroupId` 和 `strategy_effective_list` 均为可选列。可选上传 `config_level.csv` 覆盖本次计算，未上传时直接读取当前 ulinkconfig。消耗目标默认使用原模板各副本实际值；手动方式支持按 Dup1–10 分别覆盖。
- “结构降难策略 ID”只提供 `source / 1003 / 1004` 三个互斥选项；`source` 从 `config_level.StrategyGroupId` 逐模板读取，1003 与 1004 使用所选固定 ID。历史副本数据缺少 StrategyGroupId 不得报错，因为策略来源是配置表。结构策略仿真遵循“先改模板、再按 DupPara/Seed 生成 A/B”；配置缺失、冲突或非法时明确回退。
- Seed 默认联合搜索 0–31：先枚举每档可行 A/B 与 Seed，再对短名单进行整盘仿真，最后以十档联合求解避免只优化 DupPara1。Lucky 对每档保留原值；“保留原 Seed”作为快速基线；“在已观测 Seed 中搜索（含原 Seed）”会让这些 Seed 共同参与主推荐。
- 当前仿真直接使用本地可读模板与配置；IAP 保护默认未触发。版本、平台或 IAP 证据不完整只作为假设和来源提示，不禁止生成、选择或导出人工审阅草案。
- 每个模板展示 10 档最接近候选、目标与样本量、模型预估、相似历史样本、整盘仿真距离、Seed/Lucky 变化、策略和至多两个备选。训练范围内沿用原推荐规则；跨关段估值偏差 ≤25% 显示“预估接近”，其余显示“偏差较大”，不把迁移预估标为已验证推荐。没有目标时显示“无目标数据”，不得伪装成 0；提示不阻止人工导出或写入。
- 每个模板可在机械扣减基线与原参数上限之间单独指定 DupPara1 的最高 A/B 参数并重算十档。该范围不是“默认至少 7”的全局硬规则，每个模板独立判断；后续副本只使用现有的梯度转移惩罚联合排序，不额外强加通用参数差阈值。
- 结果标记“消耗预估，仅供参考”，共性迁移限制和加工源假设仅在表顶简短说明，详细口径放入使用说明。现有模型系数及倍率保护边界保持不变；未新增塔占比或关段的独立学习系数，也未声称新关段已实测。历史样本值不命名为预测值，仿真距离不命名为真实玩家消耗；历史残差区间标为误差参考，不能冒充当前关段的校准区间或人为压至 300。审阅 CSV 与参数草案保留模型版本、训练范围、迁移模式及加工源假设，支持日后用新成对测试数据升级模型。
- 提供“校准审阅 CSV”“DupPara 草案 CSV”和“一键写入配置”。只有用户明确确认写入时才修改当前配置集的 `config_level.csv`；备份和写入准备文件全部保存在工具自身的 `运行数据/配置备份/`，配置仓库不得新增备份或临时文件。工具备份路径不能位于配置仓库内，也不能通过符号链接跳出工具目录。备份失败或跨文件系统无法原子替换时保持原配置不变，不回退到配置仓库创建临时文件；不改策略表、不发布线上配置，也不自动迁移/删除历史备份。低证据或高偏差提示不构成硬阻断，由用户根据审阅结论决定是否写入。

## 9. 反馈、失败和可访问性

- 动态进度通过 polite live region 播报；终止完成、导出失败等需要立即关注的结果使用 assertive，但不重复轰炸。
- 失败信息说明对象、阶段、已保留内容和下一步；禁止仅显示“出错了”。
- 多项任务出现部分失败时，成功项仍可查看和选择。确定性无候选项就地提供“调整此模板参数”；候选未补齐、预算不足、中断或暂时性失败项统一提供“继续搜索未完成项”。
- 暂停、继续、终止、重试在生成页、导出页和任务记录中保持同一文案与状态语义。
- 所有对话框具备标题、说明、焦点陷阱、Escape 规则、关闭后的焦点恢复；高影响终止确认默认聚焦安全操作。
- 拖入文件必须有等价的“选择文件”操作；颜色状态均有文字/图标冗余；所有图标按钮有可访问名称。

### 9.1 使用说明
