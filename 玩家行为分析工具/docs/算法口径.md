# 玩家行为分析工具｜算法口径 v1.0

## 一、输入与分析单位

玩家数据推荐保留 Redash 查询输出的全部 48 列。硬校验至少包括：

```text
cohort_player_rank, user_id, event_time, client_version, platform,
level_index, level_id, level_template_id, level_play_count,
level_dup_para_id, level_dup_para, level_status, level_duration_sec,
bag_tile_change_curve, surface_normal_tile_change_curve, replay_info
```

完整样本摘要还需要 `product, cohort_max_level, cohort_max_lt, cohort_covered_level_count, event_date`。容量判断会使用 `bag_full_event_count, capacity_8_positive_evidence, bag_capacity_observation` 等字段。

业务实例固定为：

```text
level_index + level_template_id + level_dup_para_id + canonical(level_dup_para)
```

`level_id`、客户端版本、平台和用户组只保留为投放/血缘上下文。首局为 `level_play_count=1`，其他正常结算局归入非首局；两类完全分开估计。

## 二、实时局面还原

1. 解析 `interval_ms#action_id[:tile_nums]`；每步时间是距上一次操作的间隔。
2. 从配置确定模板、副本参数、随机种子和图案候选。
3. 从 `.bytes` 模板读取 TileNum、坐标、层级、遮挡和塔。
4. 沿真实点击顺序维护：剩余牌、可见牌（至少露出 1/4）、可点击牌（四格全露）、背包花色、容量、三消与释放关系。
5. 高压时计算背包装满前能否完成下一次三消，以及不同首步能否保留短窗路径。

复杂道具、塔内动态换牌、C–N 未知和容量证据不足会降低几何/花色置信度，但不会被猜测补齐。

## 三、17 个行为证据

主分层的 5 个轴：

- 节奏卡顿：每点击耗时。
- 背包压力：确定高压占比。
- 路径压缩：可见解花色不超过 1、可见无解、高压短窗无路。
- 认知停滞：可见无解时的思考时长。
- 选择陷阱：存在更安全替代时仍选择短窗不可行路径。

玩法/辅助/结果证据：半露牌负荷、单步新露出、即时三消选择、后段减速、高压恢复、每百点击主动道具、隐藏信息依赖、高压且可见无解、失败、尝试负担。

自动活动/限时扩容不计入“玩家主动道具”。

## 四、玩家内基线与跨玩家复刻

对每位玩家、每个 phase 排除当前 `level_index`，用其他关卡建立中位数/MAD 基线：比例先 logit，时间/计数先 log1p。实例效应使用玩家相对表现，避免不同玩家天然速度和消费倾向直接污染关卡标签。

候选稳定信号至少满足：

- 玩家残差中位数绝对值 `>=0.5`；
- 同方向玩家占比 `>=70%`。

正式复刻还需要：

- `N>=10`；
- Wilson 90% 下界 `>0.5`；
- Bootstrap 区间不跨 0；
- 随机对半方向一致率 `>=80%`。

`N>=20` 且随机对半一致率 `>=90%` 记为高置信。另保留留一玩家符号翻转率，检查是否被单个玩家主导。

## 五、L4–L0 / P 分层

- `L4_多维高负担`：至少 3 个主高负担轴。
- `L3_复合卡点`：2 个主高负担轴。
- `L2_单点卡顿`：1 个主高负担轴。
- `L1_稳定低负担`：无高负担轴，至少 1 个稳定低负担轴。
- `L0_未见稳定过程差异`：`N>=10`，未检出稳定过程差异。
- `P_待补样`：实例阶段玩家数 `<10`。

进度位按实例玩家暴露权重汇总：已分层覆盖低于 70% 为样本不足；复合卡点权重达到 50%/25% 对应多数/部分复合卡点；否则任一卡顿达到 50%/25% 对应多数/部分局部卡顿；其余为整体未见稳定高负担。

## 六、线上指标、内部 T0–T7 诊断与排关压力标签

线上 CSV 必需：`level_index, level_id, level_template_id, 进入人数, 人均消耗, 失败流失`。同一进度位按进入人数加权汇总消耗和失败流失；展示的关卡 ID/模板 ID 取进入人数最大的组合。

在整段序列内分别计算：

```text
center = median(x)
scale = 1.4826 * median(abs(x - center))
robust_z = (x - center) / scale
```

若 MAD 为 0，依次回退总体标准差和 1。分档：`<=-2` 极低、`(-2,-1]` 偏低、`(-1,1)` 正常、`[1,2)` 偏高、`>=2` 极高。

- T0 顺畅过渡型：无稳定高负担，消耗与失败流失均不高。
- T1 非压力消耗型：无稳定高负担，消耗偏高/极高。
- T2 轻度卡顿型：部分玩家局部卡顿，失败流失不高。
- T3 隐性流失型：压力不高，失败流失偏高/极高。
- T4 高压挑战型：多数玩家遇到卡点，消耗与失败流失均不高。
- T5 有效消耗难关：高压力、消耗偏高/极高、失败流失不高。
- T6 卡死流失型：高压力、消耗不高、失败流失偏高/极高。
- T7 超难高危型：高压力，消耗与失败流失均偏高/极高。

判定优先级从 T7、T6、T5、T4，再到 T3、T2、T1、T0，避免同关多重命中。

T0–T7 保留为内部可审计诊断，不直接当作策划排关名称。对策划展示的主标签收敛为：

- P0 轻松爽关：必须有稳定低负担的正证据，不是单纯“未检出卡顿”；适合尾号0。
- P1 平淡过渡型：结果风险不高，但缺少爽感正证据。
- P2 轻度卡顿型：局部卡顿或小谜题；适合尾号2/3。
- P3 多谜题思考型：多个局面需要思考或复合卡点稳定出现；适合尾号4/8。
- P4 高压挑战型：多数玩家稳定遭遇高负担，但失败流失尚未达高危；适合尾号5。
- P5 超难高危型：高压力且失败流失显著偏高，或高压、高消耗与高流失同时出现；只作为尾号9候选，并在表中保留风险备注。
- PX 极端负面待优化：多维高压力与极端失败流失同时稳定出现；建议优化或替换，不给正式排位。

收敛规则不是把内部代码机械改名：T2 与一般 T3 归入 P2；T4/T5 再根据复合卡点占比拆为 P3 或 P4；T6/T7 默认进入 P5 并正常排位。只有 `失败流失稳健 z>=3`、任一卡顿占比至少 50%，并且满足 L4、多数复合卡点或 L4+L3 占比至少 55% 之一时，才进入 PX。未达到 PX 的异常关不会被静默当作正常关：主表和副本表会输出风险备注，说明高失败流失、复合卡点、高消耗等待复核问题。

每个关卡副本也按 `level_index + level_template_id + level_dup_para_id + level_dup_para + 首局/非首局` 单独输出标签；样本不足时保留 PS，不强行定层。

最终关卡标签可选两种聚合口径，工作簿同时保留两种结果：

- **全部首局实例玩家加权**：按每个首局实例的 `player_count` 加权，依据可分类覆盖、复合卡点占比、任一卡顿占比得到进度位总体行为标签。
- **线上进入人数最多副本代表**：对每个 `level_index` 选取线上 `进入人数` 最多的副本，取它的首局稳定标签作为关卡标签；同时输出来源副本号、参数、进入人数与进入占比。该主副本若仍是 PS，不会回退到其他副本制造一个虚假稳定标签。

“使用道具未形成有效解决”是独立的局面级判定，不能由 T6、人均消耗或最终胜率直接替代。它要求：道具使用前已处于高背包压力、可见无解或短窗路径极窄局面；再检查使用后 1/3/5 次点击内背包是否明显下降、压力是否解除、可见解是否恢复、路径宽度是否扩张。只有高道具使用率关卡中多次出现未缓解，并同时伴随高失败流失，才作为问题关证据；否则按行为特征正常排位，并将异常证据写入风险备注供策划选关时参考。

## 七、推荐序列

当前 100 关口径以排关主标签为第一排序键。同标签不再根据消耗或流失 z 值暗中换位，而是按原关卡号升序消耗目标位置优先级。生成表 2 前可选择：

- 方案一｜双峰阶梯：风险桶从低到高进入尾号 `0,1,2,6,3,7,4,8,5,9`，在尾号 5 和 9 形成两个峰值。这是第一期的既有口径，也是默认方案。
- 方案二｜十关螺旋：P0 先填尾号0，P1 优先填1/6/7，P2 优先填2/3，P3 优先填4/8，P4 优先填5，P5 优先填9。例如 11 个 P0 会先填 `100,110,…,190`，原关卡号最大的第 11 个 P0 再填最早剩余位 `101`。
- 方案三｜单峰渐进：风险桶依次进入尾号 `0–9`，每十关持续抬升后在下一循环回落；规律最清晰，但后半段连续压力较长。
- 方案四｜多样性保护：保留双峰位置角色并审计相邻重复；当“减少同模板相邻”与“同标签按原关卡号稳定顺序”冲突时，后者优先，不自动换位。

四种方案都不改变关卡的过程压力标签和 T0–T7 分类，只改变候选位置。这是实验候选，不直接覆盖线上配置；最终仍需人工检查运营节奏并通过 A/B 或序列专项测试验证。

当前版本只对与表 1 完整对齐的连续 100 关生成推荐序列。需要覆盖更多关卡时，建议按连续 100 关分段运行；缺关、非连续或不足 100 关时会在预检阶段阻断，不强行生成推荐序列。

## 八、`config_level_list` 副本

关卡压力分类完成后，工具读取当前 `ulinkconfig/csv/config_level_list.csv`。即使存在 PX / PS，仍会按 `原关卡号 → 新推荐序列后关卡号` 生成部分重排副本：

- 只移动 `LevelId, DDALevelId1, DDALevelId2, DDALevelId3` 四列，并把四列作为一个关卡路由组合一起移动。
- `LevelIndex`、表头、类型行、中文说明行及其他所有列保持原值。
- PX / PS 不排位，它们的原 `LevelIndex` 行保留，但四列关卡 ID 留空；其余合理关填满其余位置。
- 导出 CSV 副本与 100 行映射审计，记录源文件/副本 SHA-256、方案、原位置、目标位置、留空位置、标签和四列前后值。
- 导出前后校验非留空位置唯一、已排位四列组合多重集守恒、指定位置确实留空、源文件哈希未变；任一检查失败则阻断。

工具不修改 `ulinkconfig` 中的源文件；策划确认副本后再走独立发布流程。
