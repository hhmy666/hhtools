# 玩家行为分析工具

本工具把玩家单关 TileNum 回放的实时行为分层与线上关卡三维分类固化为本地可重复流程。数据、配置、模板和结果都只在本机处理。

## 目录

```text
玩家行为分析工具/
├── 启动玩家行为分析工具.command
├── frontend/              # 原生 HTML / CSS / JavaScript
├── scripts/               # 本地服务、分析引擎与测试
├── docs/                  # 产品、设计、口径与使用说明
├── 运行数据/              # 上传草稿、任务状态与中间结果（Git 忽略）
└── 输出分析结果/          # 两阶段工作簿与审计文件（Git 忽略）
```

根目录放置双击启动器和首次使用 README。

## 使用

1. 双击 `启动玩家行为分析工具.command`。
2. 保持弹出的终端窗口开启；浏览器会自动打开本地工作台。
   如果工具已经在 `8765` 端口运行，再次双击会直接复用现有服务并打开页面，不会重复启动或显示端口占用报错。
3. 第一步导入一批或多批“玩家单关 TileNum”CSV，预检通过后运行行为分析。
4. 下载“玩家行为分层结论.xlsx”，或继续导入线上关卡副本 CSV。
5. 在生成表 2 前选择候选排关方案：双峰阶梯、十关螺旋、单峰渐进或多样性保护。
6. 第二阶段完成后下载“关卡分类与推荐序列.xlsx”和“关卡副本标签.csv”。工作簿同时包含原/新序列、副本标签、配置重排对照与内部计算审计。

首次启动及依赖安装见[工具 README](../README.md)。

## 开发运行

在本工具根目录运行：

```bash
python3 scripts/app.py --port 8765 --no-open
```

然后访问 `http://127.0.0.1:8765/`。

运行测试：

```bash
python3 -m unittest discover -s scripts/tests -p 'test_*.py'
```

## 在设置中配置的只读数据源

- 配置：`/Users/你的用户名/Projects/ulinkconfig/csv`
- 模板：`/Users/你的用户名/Projects/tile/Tile/Assets/Resources/TileMatchLevelData`
- 历史快照：`config_level.csv` 固定到 `4eac5d…`；其余回放必需配置固定到 `5022d0…`，运行时在任务目录生成完整只读快照并记录逐文件哈希。

路径、依赖或历史提交不可用时，预检会阻断分析并说明原因，不会静默替换口径。

## 分析口径摘要

- 实例键：关卡号 + 模板 ID + 副本号 + 规范化 DupPara。
- 首局/非首局分别建立玩家内基线和跨玩家复刻证据。
- L4–L0/P 只由实时过程指标决定；失败、道具、消耗与静态模板特征只作辅助或结果校验。
- 人均消耗与失败流失使用整段关卡的中位数和 MAD 分档，不按均值或四分位强制均分。
- T0–T7 保留为内部三维诊断；策划主视图使用 P0–P5 / PX 排关压力标签。PX 关卡不给正式排位，因此在处理完成前不生成可能被误用的配置副本。
- 配置导出直接读取当前 `ulinkconfig/csv/config_level_list.csv`，仅移动 `LevelId` 与三列 `DDALevelId`；不会覆盖仓库源文件。

详细规则见工具内“使用说明”、[PRODUCT.md](PRODUCT.md) 与 [UX-CONTRACT.md](UX-CONTRACT.md)。

## 安全与恢复

- 服务只监听 `127.0.0.1`。
- 如果 `8765` 被其他程序占用，启动器会明确提示且不会改动任务状态；关闭占用程序后重试，或通过 `--port` 指定其他端口。
- 原始 CSV、配置和模板均只读；中间文件只写入本工具的 `运行数据`。
- 浏览器关闭不影响后台任务；终端窗口关闭会停止本地服务。
- 已完成任务保留在本机，可在再次启动后查看；上传原始数据不会提交到 Git。
