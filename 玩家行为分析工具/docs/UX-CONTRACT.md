# 玩家行为分析工具｜UX Contract

## 主流程

1. 玩家数据：上传多个 CSV 或粘贴单个 CSV；展示文件、字段、UID、关卡范围和重复审计。
2. 行为分析：确认配置/模板路径后启动；后台任务按真实步骤更新；完成后可预览 L4–L0/P 和下载表 1。
3. 线上指标：上传或粘贴关卡副本 CSV；校验关卡覆盖、数值格式和分组互斥性。
4. 压力分类：输出 P0–P5 / PX 排关主标签、内部 T0–T7 诊断、风险备注、处理建议、关卡副本标签与候选新序列；支持“全部首局实例玩家加权”和“进入人数最多副本代表”两种聚合口径，并保留另一口径及标签来源副本用于审计。只有多维高压力与极端失败流失同时成立才进入 PX；其余异常关正常排位并保留复核备注。
5. 配置副本：始终导出独立的 `config_level_list.csv` 副本与重排对照；PX / PS 保留原关卡位置为空，其余关卡继续排入可用位置。只移动或清空 `LevelId`、`DDALevelId1`、`DDALevelId2`、`DDALevelId3`，不写入源文件。

## 组件所有权

- Select/Listbox：使用原生 `select`，接受操作系统负责弹层几何、键盘行为与中文显示；本工具只负责标签、焦点样式和校验反馈。
- Form：页面输入由 JavaScript 显式预检，原生表单声明 `novalidate`，不混用浏览器默认校验文案。
- Textarea：使用本项目原生文本域并固定尺寸，避免页面结构被任意拖拽破坏；内容区保留内部滚动。
- Button/Toast/Dialog：由 `frontend/assets/app.js` 统一绑定动作和状态，HTML 中不使用内联脚本，保持 CSP `script-src 'self'`。

## 状态机

- `empty`：无数据，主按钮禁用。
- `ready`：至少一个有效来源，允许预检。
- `validating`：只读解析输入，禁用重复提交。
- `invalid`：在卡片内显示问题清单和修复建议，保留用户已选文件。
- `queued/running`：展示真实阶段与最近日志；允许离开当前视图，不丢任务。
- `succeeded`：展示 KPI、表格预览和导出入口。
- `failed`：保留已成功的上游阶段、日志和可恢复的预检草稿；草稿存在时提供“按原输入重试”，否则明确引导回对应导入步骤重新预检。
- `supplementing`：已完成表 1 后返回玩家数据页，保留当前浏览器会话中的原始文件；新增 CSV 与原文件合并，预检通过后清除旧的当前结果引用，进入新的 `ready` 状态并按全部文件创建新任务。历史任务与已导出文件不删除。

## 输入规则

### 玩家数据

- 接受 `.csv`，文件可多选；粘贴只接受一个完整 CSV。
- 多文件 Schema 必须一致；保留原 48 列最安全。
- 不同文件 UID 必须互斥。整文件重复会被识别；跨文件 UID 冲突阻断分析，避免重复加权。
- 有效结果为 pass/win/success 与 fail/failed/lose/loss/bag_full_fail；exit/unknown 只进质量审计。
- 正常结算但 `replay_info` 为空的行逐行跳过，并在预检提示与审计中报告数量；其余有效对局继续分析。只有所有正常结算对局都无法还原时才阻断。
- 建议同产品、平台、版本范围、日期口径、关卡区间和玩家到达门槛，只改变稳定哈希排名区间。

### 线上关卡数据

- 必需列：`level_index, level_id, level_template_id, 进入人数, 人均消耗, 失败流失`。
- `失败流失` 同时兼容百分数字符串与 0–1 小数；空值、负权重、重复聚合口径或缺关会阻断。
- 同一关的展示 ID/模板取进入人数最大的组合；人均消耗与失败流失按进入人数加权。

## 导航与返回

- 侧栏切换工作台/结果不会重置正在运行的任务。
- “重新开始”只清空浏览器当前任务引用，不删除已导出文件；需要二次确认。
- 分析完成后优先停留在结果概览，返回导入页仍保留来源摘要。
- 无论当前是否存在待补样关卡，表 1 结果页都允许追加玩家样本；存在待补样关卡时该操作是唯一主下一步，覆盖已充足时作为次操作保留。
- 浏览器刷新后可以恢复历史任务结果，但浏览器安全模型不能恢复原始 `File` 对象；此时追加样本需重新选择原批次和新增批次文件，界面必须明确提示，不能声称已自动合并历史原文件。

## 错误与恢复

- 文件解析错误：指出文件名、缺失列或首个无效值。
- 外部路径错误：分别指出配置目录、模板目录、历史 Git 提交或解析器缺失。
- 后台任务失败：显示失败阶段、最后日志和本地任务目录；不暴露完整堆栈给普通用户。
- 服务重启：扫描 `运行数据/任务` 恢复已完成任务；浏览器同时保留最近一次轻量结果快照。线上阶段失败或中断时，表 1 仍可查看和下载。

## 空态、加载与完成态

- 空态说明“先导入什么”和“为什么需要这些数据”，不只显示空白表格；任务运行中则明确显示运行状态并提供返回工作台入口。
- 加载态优先显示后台实际返回的百分比和 `current/total`；后台未返回数值时显示不定进度与当前动作，不根据耗时伪造百分比。运行日志全宽换行展示，不制造页面横向滚动。
- 完成态固定叙事：数据能否用 → 哪些关/实例异常 → 哪些行为轴 → 稳定性 → 如何处理/排关 → 边界。
- 表 1 完成后必须给出唯一的下一步：有“样本覆盖不足”时，按当前实例分配比例估算最低补样人数并返回玩家数据；全部可分类时，引导导入线上指标。

## 数据与安全

- 服务仅绑定 `127.0.0.1`；上传、粘贴、模板解析和导出都在本机。
- 源 CSV、配置和模板只读；任务中间文件写入工具自己的 `运行数据/任务`。
- 下载接口只能访问当前任务白名单内的结果文件，拒绝任意路径。
