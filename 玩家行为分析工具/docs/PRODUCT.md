# 玩家行为分析工具｜产品说明

## 产品目标

把本轮“玩家回放实时行为分层 → 线上消耗/失败流失叠加 → 候选排关”的人工分析流程固化为可重复运行的本地工具。策划只需导入 Redash CSV，工具读取本机仓库中的配置和模板，输出可筛选、可追溯、可复算的 Excel 结论。

## 目标用户

- 主要用户：Tile 关卡策划、数值策划、关卡验收负责人。
- 协作用户：数据分析、客户端/关卡研发。

## 核心任务

1. 导入一批或多批玩家单关 TileNum CSV，先做 Schema、UID、覆盖范围与重复数据审计。
2. 逐步还原 replay_info，读取配置与模板，计算玩家实际经过的节奏、背包压力、路径压缩、认知停滞与选择陷阱。
3. 以玩家自己的其他关卡作为基线，再判断相同关卡实例上的其他玩家是否复刻同方向差异，形成 L4–L0 / P 分层。
4. 导入线上关卡副本数据，以整段序列的中位数与 MAD 计算消耗/失败流失分档，形成 T0–T7 三维标签与候选新序列。
5. 在四种可复算的心流方案中选择一种，生成候选新序列。
6. 读取当前 `config_level_list.csv`，导出只置换 `LevelId / DDALevelId1 / DDALevelId2 / DDALevelId3` 的完整副本和映射审计；源文件保持不变。

## 成功标准

- 首阶段工作簿包含：结论总览、关卡号分层、实例分层、行为维度、方法与边界。
- 第二阶段工作簿包含：8 标签图例、100 关 7 列结果、统一配色、逐关建议、所选方案与推荐序列；额外保留审计明细。
- 配置副本保持表头、类型行、中文说明行和非路由列逐值不变；100 个四列 ID 组合完整置换且可回查。
- 输入错误在分析前被阻断，错误信息明确告诉用户缺什么、怎么修。
- 单行正常结算对局缺少 `replay_info` 时只跳过该行并计入审计，不阻断其他可还原对局；全部正常结算对局均不可还原时才阻断。
- 所有数据仅在本机处理；源文件与仓库模板只读。
- 同一输入、同一配置与算法版本重复运行得到一致结果。

## 已确认口径

- 关卡实例键：`level_index + level_template_id + level_dup_para_id + canonical(level_dup_para)`。
- `level_id`、版本、平台、用户组只作血缘上下文，不直接进入实例身份。
- 首局和非首局分开分析，非首局不丢弃。
- 主分层只使用实时过程行为，不用失败、人均消耗或模板静态特征直接定层。
- 活动/限时自动背包 +1 不算玩家主动道具选择。
- 表 2 是 `level_index` 进度位层的序列分类，不替代实例层分析。

## 关键边界

- 可见无解与短窗无路是玩家当时信息集和有限搜索窗的指标，不是全局求解器证明。
- 洗牌、移牌、复活等复杂 Handler 后的花色/几何可能降级；工具必须在质量报告中披露覆盖。
- 单个间隔 `120000ms` 是右删失，累计时间只能视为下界。
- L4 表示多维稳定高负担，不自动等于坏体验；最终体验评价仍需策划标注或实验验证。
- 历史配置快照依赖本机 `ulinkconfig` Git 仓库；不可用时必须显式提示，不能静默改用当前配置。
