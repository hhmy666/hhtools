# 塔占比修改算法与验收口径

本文原有章节描述减少模式，继续适用于旧计划和减少任务。增加模式采用下述独立计划、追加编码和验收口径，不放宽任意旧产物的校验。

## 增加模式的独立口径

任务参数 `mode=increase` 使用独立 `increase` 对象，缺省 mode 仍为 reduce。数量四选一：count（新增张数）、multiplier（最终总量倍数）、ratio（最终塔占比区间）、manual（逐塔最终张数）。按最近真正合法结果取整，等距向上；20通常为21，但对称、锁定、区域与范围共同决定真正合法解，不能先舍入再突破占比上界。单塔不要求3倍；最终总量与A/B各为3倍。

增加仅在原数组后追加普通A/B牌。原Tile顺序、未知字段与未授权数据保留；原塔不可减牌，只有计划授权的XY、塔方向及整体平移可修改。新增方向默认0上，1/2/3为左/下/右，原塔默认保留。位置对称独立校验；方向可单塔修改。

推荐搜索上、下、左、右、中心空白和组合区域；用户可指定或自动选择新增堆数。差值/比例保持原高低关系，单塔高度修改使用manual与完整tower_counts；锁定塔不能被其他调整暗改。紧凑/分散、塔间距与塔到主阵型间距分别处理。整体平移按整数网格；自动平移建议在预览中显式呈现并由用户采用。

增加模式同样使用固定新增牌锚点安全区X=2–14、Y=2–16，同时要求2×2占位不超棋盘；不是整个网格都能用于新增。新建塔、旧塔追加牌、授权移位后的牌与修改后的塔分别执行安全区检查，不变源牌在安全区外只记录，不修理原模板。X=1/15不能成为新增塔位置，增加层数或更改方向不能豁免。

几何检查还分逻辑占位、编辑器全部层展开及客户端外框，不能以锚点在安全区内代替整塔合法。搜索时限或尝试次数用尽只说明本次未找到，不能宣称全局无解。预览接口 `POST /api/increase/preview` 只读取已导入快照，不注册可下载产物；原、新图按原序号对齐，新增index接在原牌之后。

失败恢复最多返回两个真实构建并通过独立验收的参数方案。可显式建议新建/混合改为原塔加层；若数量也需改变，逐字段记录原值与新值。方案保存完整参数、源/产物SHA及实际数量和塔堆事实；试算不注册产物。客户端采用只填入当前模板，正式重跑仍独立验收。没有验证通过的方案不伪造数值，也不能把试算中断当成全部合法位置已穷尽。

正式生成使用冻结IncreasePlan/TowerAddition证据，追加重写后由独立verify_increase复核。登记、重命名、下载、导出与同步继续重读并验收，微调后旧计划失效。新旧可信计划分别解码，禁止客户端以operation声明绕过验证。参数联动从可信产物证据确定增加，首副本half-up取整后以差值平移十副本；空侧未变保留，0到非空需补基准。

## 目标与不变条件

工具处理一个 _m.bytes 模板时，改变 Tile 位于塔内还是非塔区域以及必要的非塔坐标，并允许本次搬出的 Tile 按补牌规则转换 A/B 类型；不改变玩法所需的 Tile 总量。不搬的 Tile 保持原类型、字段与字节。

每个结果必须同时满足：

- 最终 A Tile 数量为 3 的倍数；
- 最终 B Tile 数量为 3 的倍数；
- A+B 总量与源模板一致；
- 塔 Tile 占比不低于下限，并严格小于上限；上下限均为 0 时塔 Tile 数为 0；
- 移出塔的 Tile 全部补回非塔区域；
- 生成的内部 TemplateId 与目标命名一致；
- 文件可被独立解析和再次校验。

任何一项不满足，都不能标记为“已通过”。

## 塔 Tile 占比

统一口径为：塔 Tile 占比 = 塔内 Tile 数 / 模板全部 Tile 数。

默认范围为 0%–25%，表示结果不低于 0% 且严格小于 25%，不能等于 25%。下限包含，上限不包含；正数范围要求下限小于上限，只有 0%–0% 表示清空塔。算法根据总 Tile 数将范围换算为整数塔牌数量，再结合原塔堆结构寻找实际保留数。范围内没有满足数量、类型和阵型规则的整数保留数时，明确失败，不自动降到下限以下；原塔占比低于下限时也不会添加塔牌来凑范围。

无塔模板会在导入结果中明确标记，点击“开始生成”后直接跳过：不命名、不生成新文件，不进入下载、导出或同步清单，原模板保持不变。有塔模板是否需要搬移，以生成结果中的实际搬移数量和验收状态为准；前端不会根据导入占比提前推断。

新增上层候选从当前已摆下的完整下层计算，包括本次刚补的牌。非随机策略在满足原堆叠、对称、边界及同层规则的候选中，优先尝试能压住下层新补牌的位置和堆叠组；没有这样的合规位置时仍可使用原牌。偏好不替代规则、不强制全部新牌互相堆叠。随机策略保留种子排序。每次分层试算独立复制新增位置，不沿用其他试算的支撑。该排序记录为 orbit-v2-added-support-sha256，旧已生成文件不重写；重新生成可能改变坐标。

## 塔堆保留分配

自动模式尽量保持源模板的塔阵型：

- 保留原塔堆数量，除非目标为 0 或约束使某堆必须清空；
- 维持各堆数量的相对关系；
- 原本相等的对称塔堆优先保持相等；
- 原本较大的塔堆在缩减后通常仍不小于较小塔堆；
- 分配结果满足目标塔占比和总量守恒。

例如原塔堆为 6 / 9 / 9 / 6，缩减时优先产生 3 / 4 / 4 / 3 或 2 / 4 / 4 / 2 这类关系，而不是把数量集中到某一堆。

高级逐塔模式允许策划输入每堆保留数量。算法仍会校验数值范围、对称关系、目标占比、Tile 总量和类型转换后的三消数量。若最终 A/B 不是 3 的倍数，返回对应数量及原因；只推荐已经完整生成并独立验收的保留数组合，不擅自改写用户输入。

## 补牌 Tile 类型

搬出牌的原类型与补入牌的类型分别计算。批次默认及单模板选择“自动”时沿用原规则：

- 源模板只有 A Tile：全部用 A Tile 补；
- 源模板只有 B Tile：全部用 B Tile 补；
- A/B 都有：全部补原模板全局数量较少的类型，比较范围不是塔内数量，也不随搜索过程重新选择；
- A/B 数量相同时，使用确定性选择并记录实际补入类型；

单模板设置及单独重跑可明确选择“补 A”或“补 B”，该选择优先于自动规则。推荐只看原模板非塔区域的真实数量：只有一种或一种数量更多时推荐该种；A/B 同数时两种均可；缺少证据时不猜测。推荐不会自动覆盖当前选择，点击“采用推荐”才改变补入类型。明确补入源模板没有的类型时，仍校验最终 A/B 各为 3 的倍数；原副本没有该类型的图案数量基准，一键配置新参数不能自动推算该侧，需要补充基准。

无论自动还是明确选择：
- 每堆仍从塔顶移出连续后缀，原牌可以是 A、B 或混合类型，不要求该后缀与补入类型相同；
- 只对选定搬出的 Tile 改写必要的 A/B TileId 与坐标，其 Debuff、未知字段等其他字段保留；不搬的 Tile 全部字段和字节保留。

设源数量为 A₀/B₀，搬出数量为 rA/rB，补入数量为 pA/pB。计划与独立验收分别检查 `rA+rB = pA+pB`、`A₁=A₀-rA+pA`、`B₁=B₀-rB+pB`、最终 A₁/B₁ 各自可被 3 整除，以及全部 Tile 总数守恒。A₁/B₁ 可以与源数量不同；这里的“补牌”不凭空增加总 Tile。

结果需展示搬出/补入 A/B 数量、A/B 增减和原/新总量。例如 `hr0127` 已在 25%、顶层优先、单层 20、最多新增 2 层下通过新规则验收：塔牌 37 → 19、总量 108 → 108、A 69 → 51、B 39 → 57，搬出 18 A 后补入 18 B，新增 2 层。

## 位置搜索策略

### 顶层优先

先在现有最高非塔层搜索。候选不足时可新增层，最多新增层数由参数控制。新 Tile 必须压住下层 Tile 至少 1/4 角，且不能对邻近层的单一 Tile 形成完全遮盖。

### 底层优先

先在模板整体最底层搜索。新 Tile 必须被上层 Tile 压住至少 1/4 角，同时不能被邻近层完全遮盖。它仍需要满足显示范围、对称和堆叠规则。

### 五五开

在顶部和底部候选中交替分配，尽量平衡两侧数量。若一侧先耗尽合法位置，剩余 Tile 可使用另一侧，但最终仍需通过全部验收。

### 随机

在合法顶部/底部候选中按固定随机种子选择。它只随机选择合法候选，不会放宽几何约束。相同源文件、参数、代码版本和种子应产生相同结果。

## 对称

算法先识别源模板主要对称形式，再以对称组而非单个坐标添加 Tile。

- 左右轴对称：新增坐标必须存在关于中心轴的镜像；轴上的合法单点可单独使用。
- 上下轴对称：按水平中心轴生成镜像。
- 中心对称或多重对称：候选按完整轨道成组加入。
- 无稳定对称：保持原局部节奏和质心，不强行制造新对称。

塔堆本身的成对关系和非塔外观对称分别校验。新增层不能因为候选数量刚好足够而破坏源模板的主要对称。

## 堆叠

“堆叠形式一致”以源模板同类非塔区域的几何关系为参考：

- 若该层普遍是一张上层 Tile 压住四张下层 Tile 的 1/4 角，新加 Tile 也使用一压四；
- 若普遍是一张上层 Tile 分别压住两张下层 Tile 的 1/2，新加 Tile 也使用一压二；
- 若存在多种形式，候选位置按相邻区域和该层主要形式匹配；
- 若源模板非塔 Tile 只有一种堆叠方式，不允许新增另一种方式。

在已有层补牌时，沿用该层原有堆叠形式；新增最上层时，继承紧邻下方层的压盖单位：下方层为1/4角，新层也只能用1/4角；下方层为1/2，新层也只能用1/2。下方层没有可辨认的堆叠证据时，才使用源模板的单一整体形式作为参考。新层必须形成有效支撑；可以压住下方层刚搬移补上的 Tile，不要求支撑牌来自原始位置。规划与独立验收分别计算这一规则。

重叠判定使用模板坐标和 Tile 外接矩形计算。至少 1/4 角被压表示存在有效层间关系；完全遮盖、同层非法重叠或超出允许显示边界的候选会被拒绝。

Tile 锚点安全区为 X=2–14、Y=2–16，并且 2×2 footprint 不能超出模板边界。这个边界用于避免编辑器里看似存在、客户端实际显示越界的位置。

## 搜索与失败

搜索顺序大致为：

1. 解析模板并建立 Tile、层、塔堆和几何索引；
2. 计算需要移出的塔 Tile 数；
3. 按塔堆比例或高级逐塔参数确定保留数，并计算连续后缀的搬出 A/B 数与固定补入类型；
4. 根据策略生成非塔候选坐标；
5. 联合检查类型转换后的 A/B 三消数量，并以对称组、堆叠形式、显示范围和层上限过滤；
6. 选择足够候选，重写内存中的模板副本；
7. 交给独立验收器重新解析。

自动模式联合搜索塔保留组合、搬出/补入数量、转换后的 A/B 三消数量与补牌位置。首个组合数量不合法或无法摆放时，会在原参数范围内继续搜索其他合法组合：塔占比上下限、补入类型、补牌策略、单层牌数、最多新增层数和种子不变，实际占比可以更低但不能低于下限。高级逐塔模式不会擅自改变保留数。整个搜索共用预算，未找到完整方案不等于证明全局无解。

如果候选不足，工具不会输出“勉强可用”的文件。失败结果应包含原因和推荐调整方向，例如：

- 提高单层非塔 Tile 建议上限；
- 增加最多新增层数；
- 改用另一种补牌位置策略；
- 调整高级逐塔保留数；
- 目标占比与原结构共同导致不可行。

一个模板失败不影响其他模板继续生成、验收和导出。

参数建议只展示已经完整生成并独立验收的方案；可调整层数、密度、补牌方向或手动保留数，但不得提高塔占比上限或实际塔占比，也不得改变下限或用户选择的补入类型。填入建议不覆盖用户刚修改的下限或补入类型；建议与当前范围不兼容时提示重新检查。旧版 `single_move_type_unavailable` 限制已取消，旧失败记录保留审计事实，使用原参数单独重跑获得当前结果，不要求用户先放宽参数。

## 独立验收

独立验收不是复用生成过程里的“已找到候选”结论，而是从生成后的 bytes 重新读取并计算：

1. 文件结构和字段可解析；
2. 内部 TemplateId 等于计划值；
3. 最终 A/B Tile 数均为 3 的倍数，并与计划的搬出/补入数量及类型转换计算一致；
4. 总 Tile 数一致；
5. 实际塔内 Tile 数和塔 Tile 占比满足下限包含、上限不包含的范围，补入类型满足计划；
6. 逐塔保留数与计划一致；
7. 新增 Tile 位于显示坐标范围内；
8. 新增 Tile 不被完全遮盖，也不会完全遮盖邻近层单 Tile；
9. 层间至少形成要求的 1/4 或 1/2 压盖；
10. 源模板的主要对称形式仍成立；
11. 新增位置与源模板非塔堆叠方式一致；
12. 导出文件摘要与任务登记摘要一致；
13. 不搬的 Tile 字段与字节不变，类型转换仅发生在本次搬出的具体 Tile，其他字段保持原样。

只有独立验收全部通过，产物才进入当前可下载、可导出和可同步清单。重跑模板时，旧产物退出当前清单并留在任务审计记录中，避免误下载过期版本。

类型转换信息进入新计划与任务证据。旧持久化计划缺少这些新字段时，仍按其原有“不转换、A/B 各自守恒”的口径重新验收，不据此补造类型转换；保留已验收历史 bytes。重新生成或单独重跑采用当前规则并记录新证据。

旧任务缺少范围下限或补入类型字段时，按下限 0%、补入类型“自动”兼容读取，不重写其既有产物。旧任务的非塔推荐数量可从只读源模板重新计算；读取失败则显示缺少证据，不把全模板数量当作非塔数量。

## 导出和同步的安全口径

导出、同步均分为“预览”和“确认写入”两阶段。预览计划记录目标文件当前摘要并短时有效；确认时重新检查摘要。

- 新文件：目标不存在，可以写入。
- 本地导出同名文件：无论内容是否相同，都保留已有文件，为本次产物的模板ID直接追加v2、v3等后缀，不加下划线。例如lessTxkd090_m.bytes已存在时，导出lessTxkd090v2_m.bytes；v2也存在则继续找v3。原ID本来带v1也不截断，仍直接追加后缀。
- 导出预览展示原文件名与最终文件名，不提前写入或改动当前产物。确认导出时同步改写内部TemplateId，并再次独立验收；随后单文件、ZIP下载和模板库同步使用最终新ID。文件发布使用不覆盖写入，预览后若被其他进程抢占名称，拒绝覆盖并要求重新预览。
- 模板库同步内容相同：目标摘要与产物一致，标记“内容相同，已存在”，不重复覆盖。
- 模板库同步内容冲突：目标存在但摘要不同，仍需按同步预览确认处理方式，替换前备份。同步不套用本地导出的自动版本规则。
- 目标变化或计划过期：拒绝写入，要求重新预览。

导出/同步计划必须绑定任务编号、revision、当前尝试和参数、命名规则、临时导出目录、同步目标与产物摘要。任一上下文发生变化，前端立即废弃旧计划；服务端提交时仍会重新检查目标摘要。

同步事务以单个模板为边界；同一模板同步多个仓库时会记录写入日志，后续写入失败则按日志回滚该模板已写入内容。批次内兄弟模板相互独立，因此一个模板已回滚时，其他模板仍可能已经同步成功；界面必须按实际行分别汇总，不能把混合结果写成整批无写入。

若回滚本身失败，状态必须明确显示“回滚失败，需要人工处理”，不得伪装成功。若文件写入完成但同步审计报告未能持久化，界面必须保留逐行实际结果，并明确显示“审计记录未落盘、同步已锁定”，要求人工核对。冲突确认不足属于写入前状态，原计划和确认令牌仍可用于补齐确认后重试。

## 2026-10-26：普通牌追加与增加塔对称修订

依据用户本轮确认，`mode=ordinary_add`为独立普通牌追加模式，与减少塔、增加塔分别保留计划与验收口径。下列空B基准规则仅覆盖可信普通牌产物，不追溯放宽旧减少或增加塔计划。

### 普通牌追加的不变量

- 默认`tile_type=B`、`added_tiles=18`、`placement_strategy=bottom_first`；可显式选A、`top_first`。两种策略严格只在下侧/上侧摆放，不跨侧补足。新增张数为正的3的倍数，实际新增量等于输入，不按塔模式的“最近合法量”舍入。
- `layer_mode=auto`默认最少0、最多3层；`exact`要求`min_added_layers=max_added_layers`；`range`包含最少与最多值。层数为非负int32整数且下限不大于上限，固定值/范围可高于自动默认3层，不设产品层数硬上限；0层仅使用当前所选方向的外层，不新增层或插入中间层。
- 原Tile顺序、X/Y、A/B类型和其他未授权字段保留；底层追加仅允许按计划`original_z_offset`统一增加原非塔牌Z，不能改变原非塔牌相对层差。原塔TileData与StackData字节原样保留，避免改变绝对Z决定的展开位置；新牌不进入塔。
- 新增坐标执行X=2–14、Y=2–16与完整2×2占位检查，禁止新增同层重叠、邻层一压一完全遮盖以及与塔完整展开区域碰撞；全部层参与碰撞检查，不能只看高亮牌。顶/底新增形成有效紧邻层压盖，保留真实源对称组，尽量延续原非塔堆叠。
- 从源bytes与输出bytes独立复算新增数量/类型、原牌保护、原Z统一偏移、实际新增层数、塔结构和几何；验收通过才注册为可交付产物。默认命名`moreB{原模板ID}`，导出页可改规则，同名顺延版本且内部ID同步，源文件不写。
- 最终总牌数（含特殊牌）和A/B各自数量均须为3的倍数；特殊牌不能绕过总量成组检查。

### 可信普通牌追加的副本基准

服务端以`OrdinaryAddPlan`及源/产物摘要证明`ordinary_add`，不能凭浏览器`operation`、模板名称或未校验映射放宽旧总量守恒。非零原侧沿用增加参数口径：新首副本种类数=`half-up(原首副本种类数 × 新该侧张数 / 原该侧张数)`，再把首副本差值应用到其余九副本；未变侧及种子/塔幸运值原字符串保留。

用户明确授权仅原B为0、新B非空时借用原A的每种图案组数：`new_first_B=half-up(new_B_tiles × old_first_A_kinds / old_A_tiles)`。原A张数和首副本A种类基准均需有效；计算证据标记`parameter_basis.B=source_A_groups_per_pattern`。例：60A/0B、`10|0|100|0`追加18B，得到`10|0|100|3`。B侧首副本差值仍平移其他副本，不逐副本重算密度。原A为0而新增A仍报告缺少基准，不自动借B；旧reduce/increase不使用此例外。新LevelId默认`moreB{原关卡ID}`，明确修改的规则保留。

### 增加塔对称的当前口径

增加塔以原非塔层的`(x,y,z)`多重集独立识别X反射、Y反射和180°旋转，纯塔源回退使用全部源牌；变换中心取源锚点bbox的min+max，整体平移同步平移中心。真实成立的变换才成为源对称要求；完全无严格对称的源，新增塔默认180°中心对称，不再无条件强制X反射。单行不额外引入退化Y反射。

旧塔移动和新塔位置联动对旧坐标、目标坐标同时应用同一群变换，不能用“某轴原坐标相同”猜测不需反射；冲突推导或显式覆盖冲突拒绝。独立验收重新识别源变换并检查位置组、移动授权及同平台高度，不调用规划器作证。X=2–14、Y=2–16、安全占位、编辑器/客户端完整展开、间距与区域选择仍同时约束。左下/右上双塔可满足180°对称，但并非因此豁免空间或区域限制。

新增加塔计划显式记录`symmetry_version=source-v2`。只有精确符合旧持久化结构、缺少该字段的计划按`legacy-x-v1`读取，保留其历史对称口径，避免误拒原已合法产物；当前安全区、碰撞及其他验收规则不豁免。重新生成均采用`source-v2`，未知版本与API传入版本覆盖一律拒绝，不改写历史bytes。

### 已通过结果的单独重跑

已通过结果允许继续单独调整；新attempt基于原导入快照和当前完整参数生成并重新独立验收，不能把旧产物当源累计追加。最新有效产物替代当前交付项，其余模板和历史审计证据保留；预览或打开重跑编辑器不写源文件、导出目录或配置表。

### 0.9.1：目标总数、上下分配与完整承接

本节按用户追加需求扩展前述单侧追加规则。`target_mode=count`保留精确新增张数；`total_range`接受含两端的`min_total_tiles/max_total_tiles`，按源总量推算可行的正新增数量（3的倍数），从较小数量开始试算。选择结果需同时满足范围和独立几何验收；计划保留原范围意图，不能改为未告知的固定数量。原60张、目标90–99时可补30/33/36/39张。范围无可行成组总数时返回`target_total_unattainable`。

`placement_strategy=both`允许上下同时补入；`split_mode=auto`优先接近均分的合法分配，`custom`执行`top_tiles/bottom_tiles`，两侧均为正整数且合计为3的倍数，单侧不要求成组。固定数量时合计须一致；目标范围时源总量加合计须落在范围内。新增层数为上下合计，下方可连续多层；单层源使用both时不把同一原层重复算作上下两侧，而是在上下分别新增至少一层。结果记录上下实际张数与各自新增层数。

下方新层不只要求新牌接触上层，还要覆盖紧邻上层的全部牌，包括原来最底层的原牌。规划采用覆盖选择并对不可覆盖或张数不匹配提前剪枝；独立验收从输出重新计算全部承接，返回`unsupported_upper`拒绝悬空。新增上层牌也须压住紧邻下一层；仍禁止相邻一压一全遮盖，延续重叠单位与实际对称。历史普通牌产物适用当前承接检查，不通过时需重生成，源与历史文件不改写。

### 0.9.2：已满足总数与自动搜索公平性

源总数已在目标区间时，任务记为no_op，不命名、不生成产物，明确显示原/最终数量相同，并建议仍需补牌时切换新增18张后重新试算。算法预览返回already_in_range。旧产物仍按原计划独立复验，不自动删除或改写。

上下自动分配先浅搜各个层数/数量组合，再对未完成组合深入搜索，避免前面的密集分支耗尽全部时间。仍采用相同总体计算限制，不将试算未完成解释为全局无解。失败摘要保存原总数、A/B及塔牌数量；旧失败记录读取已校验的原始快照补全展示，不从成功产物反推，也不将未知结果数写成0。

## 2026-11-09：硬性承接检查与交付阵型平移

本节替代前文“原有悬空仅作警告、原样保留”的交付口径。减少塔、增加塔、增加普通牌及其历史产物，在生成、注册、恢复、下载、导出和同步时均执行当前结构验收。

- 每张非塔普通牌的 Z 大于 0 时，都必须与 Z−1 层的非塔牌有实际 1/4 或 1/2 压盖；被上层牌压住不能替代底部承接。底层为 Z=0，不能把缺少下层的高层解释为底层。
- 相邻两层普通牌禁止同 XY 的一压一全遮盖。StackData 声明的塔自身在序列化格式中共用 XY，按塔方向展开；该格式不解释成普通牌全遮盖，塔仍需连续层及完整展开边界验收。
- 规则检查覆盖全部输出普通牌，原牌、特殊类型牌及未搬移历史牌都不能绕过。发现违规时没有可交付产物，不自动删牌、改层或放宽要求。
- 预览牌的提示展示紧邻下层承接 Tile 序号和压盖面积。单层查看时，承接证据仍来自完整实际模板，不因隐藏下层而宣称悬空。
- 验收结果的阵型对比支持新模板整体按格上下左右平移及复位。所有 TileData 和 StackData 的 X/Y 使用同一整数偏移，Z、牌型、方向和未授权字段保持。移动后重新独立验收、保存为新产物；原模板快照不变。
- 平移量相对本次生成的初始产物累计，不能重复对已平移 bytes 叠加同一绝对偏移。复位恢复初始生成阵型，但仍需满足当前安全边界。平移同时检查 X=2–14、Y=2–16 及塔完整展开范围。
- 平移使旧下载能力、导出和同步预览失效；后续交付使用新产物。副本参数配置解包原生成计划并沿用原数量算法，因为整体平移不改变 A/B 牌量。并发或过时产物的移动请求拒绝，失败不撤销之前合法的已保存阵型。
