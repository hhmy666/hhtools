# 低扰动全遮盖修复方案与 Implementation Plan

> 使用 executing-plans 在当前已存在的 codex/tower-ratio-reducer-tool 功能分支顺序实现；用户明确要求自主审阅后推进，不再次等待方案批准。测试遵循test-driven-development；最后安排独立只读复审。工程外原模板、配置和其他工作区改动不写入。

**Goal:** 在保留原模板非塔表面和非塔外轮廓、塔阵型关系的前提下，提高修复成功率，优先少改牌而非追求通过数量。

**Architecture:** 保留现有protobuf改写、几何检测、编辑与任务框架；独立低扰动约束模块同时负责搜索候选和出站核验，服务端重新核验，不信任引擎自报。搜索采用分级有界回溯，失败原字节保留；原有撤回、问题定位和混批导出保持。

**Tech Stack:** Python3.9+ / unittest / 原生Web / node:test / CUA。

**Spec:** 用户本轮三条批注及正文，并以之后“塔不管外轮廓，塔本身阵型一致”的澄清为准。

## 业务边界与方案比较

- 已确认：默认删上方问题牌；可改选下方/中间问题牌。可将删除、补承接、补回数量作为完整方案验收，不在中间临时悬空时直接退出。
- 已确认（执行中用户补充）：非塔表面和外轮廓不动，保留其他露出牌；塔不受自身外轮廓限制，只保持原阵型关系。全遮盖上方删除后允许同XY同类型下方牌自然露出，不能用改牌型掩盖表面变化。非塔投影并集逐矩形精确一致，禁止只比包围盒；塔增加不能盖住其他原露出非塔牌面。
- 已确认：非问题隐藏牌移动限0..3张；必须原本完全被遮住，挪走后不影响原露出面。有限搜索由0张逐步增加，XY和Z移动均计入一张；不能把整层压缩当作零改动。
- 已确认：优先总数/牌型数量不变，必要时最终净增减<=3张；作为更保守的工程判定，全部牌型数量变化绝对值之和也<=3，不能大量A换B后只看净值。A/B及总数仍三张成组；不修改保留牌的类型。
- 已确认：塔改动最后兜底，既有塔成员增、删、移动合计<=6张；保持塔锚点/方向/描述、等高组和严格高低关系，不新建/清空塔。塔自身表面和外轮廓可增长，但不影响非塔原露出牌。
- 决策：不做全盘重排；不把原有悬空一概放行。源模板可有问题供搜索修复，但最终必须全部无悬空、无同层冲突、零全遮盖、坐标合法。原有其他错误确实无法在预算内修好时保留原样并明确原因。
- 方案比较：只加搜索时间不解决候选动作过窄；大规模重排虽可能提高通过但不符合体验约束。选择分级小改动搜索：不动塔+同数量 → 不动塔+少量隐藏重排 → 不动塔+少量数量变化 → 最后塔内<=6张兜底。每级优先隐藏牌移动少、问题牌改动少、位移短；预算未完成不能声称穷尽。
- 不承诺线上表现相同：几何/数量/阻挡关系是可测代理指标，不是线上胜率、时长、道具消耗的等效证明。结果显示具体改动数量与限制，不输出无依据的体验分数。

## Review Focus

1. 包围盒相同但非塔轮廓局部改变、塔投影盖住普通露出面、不同牌型下层替代都必须拒绝；塔自身外轮廓增长不误拒。
2. 3张隐藏移动、6张塔变化、±3总量要与输入身份逐张比较，不能靠引擎自报或重排索引绕过；未知TileData字段仍保留。
3. 临时悬空不得提前失败；最终支撑必须按紧邻Z-1几何检验，新增牌互相承接须检查完整方案。
4. 原始缺陷/大量层高与分支爆炸时搜索有界，进度持续，预算未完成明确保留；重复修复不得无限漂移并逐次越过源模板累计限制。
5. 服务端独立检查输出来源、类型、数量和低扰动规则，净增/减后的undo、比较、导出不漏牌、不伪报。
