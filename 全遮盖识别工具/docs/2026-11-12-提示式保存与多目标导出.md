# 提示式保存与多目标导出 Implementation Plan

> 使用既有分支顺序集成，独立引擎、编辑器与文件交付子任务并行；遵循TDD，最终独立复审。用户已明确要求直接修订，不再次等待方案批准。

**Goal:** 全遮盖、悬空及摆放问题仅提示、不阻止人工保存或新模板导出；总数及A/B各自三张成组仍为硬限制。机器不被原有悬空挡住，导出与塔占比工具同流程。

**Architecture:** 区分可解析/可序列化的技术有效性与业务诊断；保存检查技术有效性及总数/A/B各自三张成组。机器独立审核允许原有、身份位置不变的悬空，仍禁止新悬空和残留全遮盖。导出按修改与勾选范围，提供只读预览、确认写入、ZIP和可选同步目录；安全命名、版本、逐文件写入进度。

**Tech Stack:** Python3.9 / unittest / 原生Web / node:test / CUA，保持既有字体、字号、布局及蓝绿色。

**Spec:** 2026-11-12本轮用户全文与三张截图；取代此前“保存前清除悬空/全遮盖”和“只有通过项可导出”的限制。

## 范围与决定

- 人工编辑：全遮盖红框，悬空蓝框（含塔实际投影），分别定位；同牌两类可叠加表达。安全范围不检查、不标记；int32序列化、来源合法性、文件名/路径安全、并发版本仍保护数据，不是关卡规则限制。几何、重叠仅提示；成组是硬限制，总数及A/B各自必须为3的倍数（含塔），0张按0倍数处理。
- 机器：原悬空不要求修复，原牌身份/位置不变时允许保留；悬空全遮盖仍是红框全遮盖目标，不能豁免。其余低扰动、非塔表面轮廓和塔阵型/改动量限制保留。不新增悬空；原有越出所谓安全范围的牌保留，不强改。
- 导出：未勾选默认全部有修改的新模板（机器/人工）；勾选只包含选中且已保存有修改项。跨页勾选、当前页全选、选中数量/清空；未保存编辑仍须保存后交付。
- 与参考工具同流程：命名规则、默认工程内输出模板目录、可选模板仓和Tile编辑器仓同步、预览清单后确认写入，显示整批真实进度和逐目标结果；默认不选同步。不执行仓库Git操作/发布，不静默覆盖源文件或已有文件，重名自动加v2/v3，预览后发生竞争须重新预览。
- 根目录继续只放启动器和工程目录；新增输出及验收资料在工程目录内。实际测试仅写本工具输出/临时目录，不把测试文件写进真实仓库。

## Review Focus

1. 悬空全遮盖与普通悬空不混淆；实际塔投影支撑，而非只比原锚点。
2. 任意摆放保存/导出，允许负或边界外坐标、同层冲突；未三张成组仍阻止保存导出；损坏二进制和伪造来源仍拒绝。
3. 原悬空可保留，不允许靠重新编号或删除其他承接产生新悬空而冒充旧问题。
4. 已修改状态以原字节比较，撤回原样不再默认导出；跨页选择、失败机器项但人工已改、仍有问题已保存均正确交付。
5. 多目标命名一致、原模板不覆盖、符号链接/路径穿越和预览后文件变化不能破坏文件；部分目标失败不伪报全部完成。
