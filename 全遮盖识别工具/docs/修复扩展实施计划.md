# 全遮盖评估与修复扩展 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans for each bounded implementation domain. Steps use test-first verification; agents edit disjoint files.

**Goal:** 导入后进入独立结果页，支持改前改后对比、红框定位、自由编辑、新模板命名导出，以及保守自动修复。

**Architecture:** 延用本机 Python 标准库服务和原生 HTML/CSS/JS，扫描引擎不改变。原文件保持只读；每行结果在服务内存保存源文件与新模板修订，所有导出重新校验。复用既有工具的坐标、层级、鼠标锚点表现。

**Tech Stack:** Python 3.9+ / unittest / JavaScript node:test / HTML CSS / CUA browser QA.

**Spec:** 用户 2026-11-11 追加需求与本文件“业务约束”；既有 docs/DESIGN.md。

## 业务约束

- 两步独立页面：导入 → 评估及修复，结果页可返回导入，不与导入表单上下堆叠。
- 同一弹窗左右显示改前、改后，尺度与层级同步；问题牌红框，可按问题坐标切层定位。
- 指定层仅操作该层；无限制显示全层、自动落层；编辑时不阻拦暂时不合法的摆放，保存时明确核验。
- 自动修复默认删每个全遮盖对的上方牌；删除后若引起悬空则本模板失败原样保留。
- 用户确认：除所删问题牌外，原本露出牌不动且不被新增牌压住；同位置下层自然露出允许。新增牌全部隐藏于既有牌下，保持俯视轮廓；删除几张补几张，保留牌型数量。
- 补位在已有低层/中间层，紧邻上下层都要有正面积承接，不能新建一压一或悬空全遮盖；所有结果复扫。无解/预算未完成如实区分，不宣称数学无解。
- 同批失败隔离；成功的新模板仍可编辑、保存和导出。原始源文件与配置不覆写。
- 批量命名允许前后缀与 {原模板ID}；重名自动 v2/v3；文件名与内部ID相同；不能覆盖源模板名。
- 人工保存核验坐标、同层冲突、悬空与三张成组；仍有全遮盖可保存草稿但不可混入“修复通过”的导出。
- 塔占比工具产品名称改为“塔占比修改及增加Btile工具”；工程目录和已有调用路径不移动，避免破坏启动器与历史链接。
- 提交与推送仅本次相关文件；现有其他脏工作区内容不混入，不修改关卡CSV、不发布CMS。

## 接口与分工

1. `covercheck/repair.py` + `tests/test_repair.py`：`rewrite_tiles(raw, tiles, new_id=None)->bytes` 保留未知元数据；`validate_board(raw)->dict{valid,errors,analysis}`；`auto_repair(raw)->dict{status,raw?,reason,removed_count,added_count}`。
2. `server.py` + 新修复接口测试：保留源/当前字节；行详情兼容现有字段，增加 `original_board,revision,edited,repair_status`；POST行edit支持 `{tiles,revision}`，返回完整行详情；POST `/api/tasks/:id/repair` 异步逐项修复，GET repair 状态；POST `/api/tasks/:id/export` `{pattern,indices?}` 生成内存ZIP，GET导出包。源文件不写盘。
3. `frontend/assets/editor.js` + `editor.css` + JS测试：`CoverEditor.open({board,original,onSave,onClose})`，原生dialog内左右对比、同步层、红框问题、增删、撤销、鼠标tile方形锚点。保存调用主界面onSave(tiles)，成功后更新显示。
4. 主代理：`index.html/app.js/styles.css/view.js` 的分步导航、机器修复进度、批量命名导出入口、编辑器连接；旧工具可见产品名称替换；使用说明和交叉验收；最后定向Git提交推送。
